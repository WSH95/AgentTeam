## 2. Substantive findings

**R1 — CRITICAL (push-blocking) — undeclared `click` dependency breaks core
installs.** `commands/profile.py` §imports (`from click import Abort`, also
`tests/integration/test_profile_probe.py`) imports the external `click`
package, which is not among the three permitted runtime dependencies
(pyproject §project.dependencies: typer/pydantic/pyyaml — M1a plan §5). The
locked typer 0.27.1 *vendors* Click (`typer._click`) and does not depend on
the external package; `click` reaches the environment only through the
optional `clawteam` extra (clawteam → mcp → uvicorn → click). Consequence,
reproduced by this review: after `uv sync --frozen --all-groups` (the exact
core-leg CI sync), strict mypy reports 2 import errors, pytest aborts with 7
collection errors, and **every** `atm` command raises
`ModuleNotFoundError: No module named 'click'` via `cli.py` → `commands/
profile.py`. A push at `317bb52` would have failed all six scaffold legs (the
three `clawteam` legs sync the extra and stay green). The G5 sessions'
verification block always ran with the extra installed, which masked the
defect. Fix (applied 2026-08-24 on the owner's instruction, own commit):
`from typer import Abort` — typer re-exports the vendored class.

**R2 — MAJOR — prompt-time Ctrl-C/EOF exits 1, not the contractual 130.**
`_confirm_call` caught the external `click.Abort` around `typer.confirm`,
but typer 0.27 raises its own vendored Abort — a different class in every
environment — so the KeyboardInterrupt conversion never fired: a real
Ctrl-C/EOF at a probe confirmation prompt propagated to typer's standalone
handler ("Aborted.", exit 1), skipping the cancelled-status rows,
re-diagnosis, and `Exit(130)` (ADR 0026 contract). Evidence and profiles are
unharmed on that path (the abort fires before `capture.begin_call`; all
prior calls are already terminal and their row updates committed). The suite
could not see it: `test_cli_prompt_interrupt_exits_130_before_a_vendor_call`
monkeypatches `typer.confirm` to raise the same external class the code
catches — a tautology. Fixed together with R1; the test now raises
`typer.Abort`, the class the real prompt raises. A follow-up test driving
`typer.confirm` itself (EOF on the input stream) is filed with the pre-G6
tasks.

**R3 — MAJOR (G6 path) — managed-skills lease leak in the runner.**
`run/runner.py` §`_run_body`: the early `return … exit_code=1` for a
workspace-copy hash mismatch, and any exception outside
`(RenderError, EnvironmentConflictError, TargetError)` (e.g. `OSError` from
archive writes) escaping leg preparation, exit through no cleanup — leases
acquired for earlier legs are never closed, so the Assistant's Skills stay
installed in the owner's persistent `CLAUDE_CONFIG_DIR/skills` and the lock
fd is held until process exit. Violates ADR 0026's "cleaned in `finally`".
No test exercises the mismatch path. Fix shape: one `try/finally` spanning
prepare + execute that closes `skill_leases` idempotently. Filed as a pre-G6
task (ADR 0032).

**R4 — MAJOR — probe timeout kill-escalation has an unbounded branch.**
`profile/probe.py` §`_run_probe_process`/`_terminate_probe_process`: after a
timeout, the process group is SIGKILLed only if the *direct child* survives
the 0.5 s SIGTERM grace. If the direct child exits within the grace while a
SIGTERM-surviving descendant keeps the pipes open, the group SIGKILL is
skipped, the 10 s drain times out, `process.kill()` is a no-op on the reaped
child, and the final `communicate()` blocks **without timeout** until the
orphan exits. Attended Ctrl-C recovers through the correct
cancelled-capture/130 path (and the one real G5 timeout took the healthy
branch — SIGKILL recorded in capture `…971ee2af`), but the stall-bounding
claim behind RISKS R32's mitigation does not hold on this branch. The
rewritten `harness/process.py` handles the same situation with bounded waits
and a synthetic abandoned-pipes record; the probe runner should match it.
Filed as a pre-G6 task.

**R5 — MAJOR (latent) — adapters select the first *verified* ladder channel,
not the first *current-verified* one.** `harness/capabilities.py`
§`capability_is_verified`/`select_verified` ignore `cli_version`/
`verified_at`; `RenderContext` does not carry the observed version, so the
render path cannot check currency. Preflight requires only that *some*
ladder member is current, so a hand-edited profile with a stale-verified row
ahead of a current one passes preflight and renders through the stale
channel — deviating from ADR 0026's "first current `verified` channel".
Unreachable via normal probe flows (call 1 re-stamps ladder-first rows at
the observed version), but the invariant is undefended at the consumption
point and untested for mixed-currency ladders. Filed as a pre-G6 task.

**R6 — MAJOR (G6 evidence fidelity) — the live Codex `-o`/JSONL disagreement
is computed and then discarded.** `harness/codex.py` §`extract_structured`
records the disagreement into `problems`, but `ParsedLegV1` problems are
never persisted (`run/runner.py` §`_execute_leg` copies only
review/schema/usage/observed; `HarnessInvocationV1` has no such field), so a
live leg whose JSONL telemetry contradicts the authoritative `-o` file
archives as clean SUCCEEDED with the disagreement recoverable only from raw
streams. Probe-time disagreement *is* captured (the `event-mismatch`
coverage) and a missing `-o` file does fail the leg. Secondary defect: the
*agreement* note is appended to the same `problems` list — a latent
false-flag if problems are ever surfaced. Filed as a pre-G6 task.

**R7 — MAJOR (process) — the approved plan was amended in place with no
amendment record, and its budget text no longer reconciles.** The plan
header still reads "Plan revision: r3, 2026-08-23"; §22's revision record
ends at r3; no ADR names the plan file or the sections amended (the ADR 0022
convention). Every hunk has ADR substance (0026–0030 — traceability table in
the review workpapers), but the amendment event is untraceable from the
document. Separately, §3 (G5 gate row), §11, §12, and §18 still say "at most
two calls per harness" with no note, QUESTIONS' ADR 0020 record is
unannotated, and the §12 across-M1a arithmetic (2×3 probes + 8 + 2×8 = 30)
is stale: 9 probe calls are spent, so a cycle plus two confirmed reruns
(9 + 8 + 16 = 33) would breach the 30-call hard ceiling mid-flight. Owner
ruling (ADR 0032): a reconciling amendment + ADR is drafted for approval —
remaining budget 21 calls; the ceiling, not the reruns, binds.

**R8 — CRITICAL (push-blocking) — the home-existence gate breaks the CI
deterministic-acceptance step.** `549804f` made live preflight require every
guarded harness's config home to exist before any launch. The fake profile's
homes (`examples/profiles/.agentteam-local/vendors/<h>`, resolved relative
to the profile file) are provisioned only by `tests/conftest.py`, which also
removes them when pytest ends. The CI acceptance step
(`.github/workflows/ci.yml` §"Deterministic acceptance") runs after the
pytest step and creates nothing, so `atm run examples/run-requests/
direct-review.yaml --config examples/profiles/ci-fake.yaml` now exits 2 with
"config home does not exist" for all three harnesses — reproduced by this
review in both dependency modes. The step was green at G4 (`b8d5f9d`)
because the gate did not exist yet; the G5 sessions never re-ran the
CI-only steps after changing preflight (H4's sibling gap), so it went
unnoticed. The render-only smoke is unaffected (`live=False` skips the
gate) — the gate is doing its job; the step must provision the disposable
homes. Fix (applied 2026-08-24, own commit): the acceptance step gains a
`mkdir -p` of the three fake vendor homes, mirroring the conftest contract.
Discovered after the owner's §5 rulings, during the post-R1 re-verification;
applied under the same fix-now/push-after-green ruling and reported to the
owner in the session summary.

## 4. What the review credits

captures whose recorded hashes all recompute; atomic assessed-rows-only

every consumption site, fail-closed on API/base-URL conflicts; the Claude
argv honors ADR 0028 to the letter (Skill allowed, write/shell/web denied,
no `--safe-mode`/`--bare`); the Grok argv fix and dual field-spelling match
ADR 0029/0030; and the fakes genuinely re-derive markers from the real
channels rather than hardcoding success. The steward narrative is consistent
across six files down to individual millisecond timings, and each budget
overage has a real decision artefact. R1 aside — one import line — the gate
was closed on real, verifiable evidence.
