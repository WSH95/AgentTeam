# Independent review — M1b plan r2 at `54728c8`

This file records the second-round review verdict verbatim as delivered.
The six numbered findings are implementation-blocking; the three
"additional corrections" follow. Resolutions are tracked in the plan's r3

## 1. Verdict (verbatim)

do not approve M1b r2 yet. I reviewed frozen commit 54728c8; r2 resolves
much of the original review, but six implementation-blocking gaps remain.

### Approval blockers

1. High — pending RunRecordV1 is not representable.
   The team variant requires substrate.namespace, substrate.snapshot, and
   independence.achieved docs/plans/m1b-team-foundation.md:332, but the
   pending record is written before the space or snapshot exists
   docs/plans/m1b-team-foundation.md:646. Specify lifecycle nullability:
   pending permits null namespace/achieved/snapshot; success requires all
   three; failed/cancelled records allow missing snapshot when creation
   or copy-out failed.

2. High — provider task semantics remain incomplete.
   The plan does not define:
   - Stable topological registration when blocked_by references a
     later-declared task whose provider ID does not exist yet.
   - Provider-neutral task DTO/return shapes and whether ownership is
     projected.
   - Status translation. The run layer sends running
     docs/plans/m1b-team-foundation.md:729, while the pinned ClawTeam
     seam accepts in_progress
     tests/compatibility/test_clawteam_qualification.py:71.

   Define a protocol status enum, running ↔ in_progress adapter mapping,
   run-only handling of failed/abandoned, and deterministic topological
   creation with declaration-order tie-breaking.

3. High — team results remain code-review-specific.
   Every successful member must still produce NormalizedReviewV1, and
   handoff summary is taken from NormalizedReviewV1.summary
   docs/plans/m1b-team-foundation.md:706. The current harness protocol
   likewise parses every normal invocation as a review
   src/agentteam/harness/protocol.py:35. Consequently, the new
   "implementer" is actually required to emit review JSON.

   Introduce a provider-neutral task-result contract, or explicitly defer
   generic team execution and constrain M1b accordingly. deliverables
   also cannot mean every invocation artifact: those include raw
   stdout/stderr, while predecessor workspace changes are neither
   archived nor propagated to the successor.

4. High — automatic handoffs contradict reviewer independence.
   R2 sends a mailbox handoff across every dependency edge
   docs/plans/m1b-team-foundation.md:706, including implementer →
   reviewer, while the fixture declares independence between those
   members docs/plans/m1b-team-foundation.md:839. The normative model
   defines that independence as no message edge and blinded inputs
   docs/discovery/team-execution-model.md:52. Test transport on a
   non-independent edge and explicitly suppress or sanitize the reviewer
   edge.

5. High — failed-routed still has no green-CI completion path.
   G5 can close after ClawTeam lifecycle/conformance failure
   docs/plans/m1b-team-foundation.md:131, but the three ClawTeam jobs
   still collect those tests docs/plans/m1b-team-foundation.md:988. The
   plan does not say how M1b closes without retaining red CI. Define the
   failed branch: provider remains unregistered/unsupported, the failing
   reproduction is retained as dated evidence, and required CI remains
   green.

6. High — finalization and its fault matrix conflict.
   Examples:
   - Step 11 says manifest before terminal record
     docs/plans/m1b-team-foundation.md:671, while the normative invariant
     correctly requires terminal record before manifest
     docs/plans/m1b-team-foundation.md:757.
   - create_space failure skips cleanup, but every fault row requires a
     provider-cleanup event docs/plans/m1b-team-foundation.md:956.
   - The claimed per-operation matrix omits runtime-used receive and
     read_snapshot.
   - After a task failure, unrelated not-yet-launched tasks need an
     explicit abandoned transition to satisfy the all-terminal invariant.

### Additional corrections

- Medium — schema fixture shape: minimal_payloads() is keyed uniquely by
  schema filename tests/conftest.py:52, so it cannot contain "one payload
  per run-record variant" as written
  docs/plans/m1b-team-foundation.md:127. Keep the direct payload there
  and add a separately parameterized direct/team fixture.

- Medium — containment test is insufficient: checking only the text
  import clawteam docs/plans/m1b-team-foundation.md:928 misses from
  clawteam..., dynamic imports, and ClawTeam-specific branches without
  imports. Use an AST import scan plus an allowlist for every clawteam
  source reference.

- Medium — process-root lifetime: pinning ClawTeam's process-global root
  inside each run directory docs/plans/m1b-team-foundation.md:536 makes a
  second TeamRun in the same process fail the seam's one-root rule
  src/agentteam/compat/clawteam.py:81. Choose a stable process root or
  explicitly restrict M1b to one run per process and record the M2
  migration.

## 2. Disposition

Every finding was independently re-verified against the tree at `54728c8`
by the executing session before any resolution work (all nine confirmed;
the fresh check was the seam's `in_progress` task vocabulary and caller
lock). Resolutions land as plan revision r3. Owner decisions on this
round (ADR 0040): finding 3 resolves by **introducing `MemberResultV1`**
(the provider-neutral member-result contract, the larger path); correction
M3 resolves by the **stable `~/.agentteam/clawteam/` process root**,
restoring the ADR 0015 design. This record is valid for `54728c8` only.
