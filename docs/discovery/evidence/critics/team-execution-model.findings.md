# Critic findings — `docs/discovery/team-execution-model.md`

Label: critic:team-execution-model · Date: 2026-08-22 · Document version reviewed: file mtime 2026-08-22 12:15 (status: draft)

## 1. Verdict

**PASS-WITH-MAJORS.** No claim in the document contradicts the evidence it cites (34 citations opened, 0 factual failures, 5 mis-anchored to a neighbouring finding). The three pressure tests follow scenario → substrate walkthrough → breakpoints → minimal addition and are grounded in probe-verified ClawTeam behaviour. Four MAJORs block the owner's read-through: (1) the §11 substrate-mapping table quotes fit cells with no `[ev:…#Fn]` citation and no row→requirement mapping, and two cells misquote the fit-gap; (2) §4's "fully rendered command makes ClawTeam a pure coordination substrate" omits the mechanism — ClawTeam's adapter still rewrites argv for recognised basenames, appends `-p <prompt>` when a task is given and runs `os.getuid()` under the default config [ev:clawteam-spawn-platform#F1][#F5][#F10], which `architecture-options.md` §4 already corrected (wrapper with unrecognised basename, no `--task`, `skip_permissions=false`); (3) §5's minimal addition says the dynamic-member gate "lives where the spawn call is made" without addressing that the Lead's own shell holds `CLAWTEAM_BIN` and can call `clawteam spawn` directly — `architecture-options.md` labels TC-05 "gate + convention + shim + reconciliation", this document does not; (4) the nesting contract (§6 item 4) does not record the achieved isolation level (`namespace | data-dir | mechanical`) that `architecture-options.md` §8 explicitly asks this document to adopt and that `minimal-poc-plan.md` §5 already uses for PoC C's first pass criterion. The rest is MINOR/NIT: a step-ordering contradiction in §3.1, two glossary slips, a thin macOS/CI story in §10, a Hermes `--usage-file` vs `chat -q` mismatch, and a few uncited or mis-anchored claims.
