# Findings — assistant-domain-model.md

## 1. Verdict

**PASS-WITH-MAJORS.** No citation contradicts its evidence (≈40 of 75 unique `[ev:…]` citations opened, all supported or merely imprecise), no requirement is re-authored, no demoted ATM noun re-enters, and the content model / exclusion list / Capability-vs-Artifact / harness-policy-as-data / overlay sections cover the brief items this document owns. Three defects must be fixed before the owner's review: (1) the Ephemeral Assistant definition in §8 carries `origin{…, run: <run id>, …}` — a run identifier inside a definition, which the document's own §4 validator class "Session/run identifiers" forbids and which `team-execution-model.md` §5 and `architecture-options.md` (archive roster entry) place on the Member/archive record instead; (2) the EV pressure test in §9 has no walkthrough on any substrate as it exists today — its "Walkthrough" is the target design, the substrate facts appear only as a breakpoint list; (3) the §3 "Edited by" table and the §9 per-field conflict table give two different overlay rule sets for `principles`, `preferences`, `collaboration` and `harness_policy`, for an M-priority requirement (EV-02) whose whole point is defined conflict rules. The remaining findings are citation-precision, glossary and cross-document alignment items.
