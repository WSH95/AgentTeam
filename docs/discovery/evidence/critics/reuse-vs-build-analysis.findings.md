# Critic findings — `reuse-vs-build-analysis.md`

## 1 Verdict

**PASS-WITH-MAJORS.** The document does what its frontmatter promises: every one of the 54 `G-*` gaps from the fit-gap consolidated list gets a rung, a source, a licence, cost/risk/platform and an `[ev:…]` anchor; the "Best existing" cells match the fit-gap list cell-for-cell; the fork is classified in the brief's five classes; the licence table is complete; it never states the smallest-layer answer and never ranks the eight options. I checked ~125 citations (every citation under the key conclusions in §1, §2 TE/HB rows, §3, §4, §5, §6, §7 plus a random sample across all ten evidence files) and 14 file:line / line-count claims against the read-only checkouts: **no citation contradicts its evidence**; two are mis-anchored (F34 for "112 commits" = F1; atm F7 for the outcome vocabulary = F10) and a handful of precise numbers (DG/DT/Hermes line counts, PR #159 guard text, kit MIT, HM/OC permission flags) are correct but carry no anchor. The three MAJORs are methodological, not factual: (1) G-TE-08's cheapest rung is mis-stated — the cited evidence F20 itself names a rung-1 configuration path (`skip_permissions=false`, which architecture-options adopts) that the document never mentions; (2) the bolding rule of §1 ("6 object; 1 to materialize") is applied inconsistently across AD/EV/TC rows, so the "rung 1: 20 · rung 6: 23" tally quoted downstream is not reproducible from the rule; (3) the summary claim "rung 3 is never the only path — every ClawTeam fix has a rung-2 equivalent" is unsupported by the only two rows whose bold rung is 3 (G-TC-04, G-TE-08), and architecture-options leans on it. None of these changes the substantive conclusion ("most rung-6 items are data objects"), but each changes a number or a rung that another document quotes, so they must be fixed before the owner's read-through.
