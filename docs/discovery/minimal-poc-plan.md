# Minimal PoC plan

> Reading guide. This document defines three proofs of concept and nothing else: no code, no schedule, no implementation plan. The acceptance criteria are those of `product-intent.md` §4, quoted verbatim and then made measurable; none is weakened. Terminology follows `evidence/glossary.md`; "leader", "worker", "agent" and "session" appear only as ClawTeam's, Claude Code's or Codex's own words. Each PoC is designed to PROVE or FALSIFY the layer stated in §1, on this host first.

## 1. Purpose and the layer under test

Discovery answered "what is the smallest new software layer" in `architecture-options.md` §5; the PoCs are the first evidence that could falsify it. PoC A exercises the PoC-A slice (schemas, overlay resolver, two HarnessAdapters, HarnessBroker, `direct` launcher/wrapper, ledger, Ensemble record); PoC B the run layer over the ClawTeam-CLI CoordinationSubstrate; PoC C the nesting contract. The answer, restated verbatim from [model:architecture-options#5]:

**The smallest new software layer is** a thin, format-independent Assistant/Team layer — working name `ats` — that owns only the data no existing system has and reaches everything else through two declared seams with one implementation each. It owns, as substrate-neutral data: Assistant definitions (closed schema + exclusion validator), TeamTemplates composing Assistants by reference, Base/User/Reviewed-Evolution overlays with a deterministic resolver and a Proposal/review record, HarnessProfiles as data plus a HarnessSelectionPolicy resolved per invocation (user > Assistant > team > default), a HarnessInvocation ledger and an Ensemble synthesis record with per-invocation attribution, an artifact manifest + lock + per-host resolution report, and a TeamRun record with two roster projections (user-visible vs archive), a dynamic-member gate, a nesting contract (parent link, result carrier, isolation level recorded, stop-before-cleanup) and an archive. It declares exactly two seams — **HarnessAdapter** {profile data, injection recipe, invoke, parse} and **CoordinationSubstrate** {create_space, add_member, create/update/wait task, send/receive, snapshot, stop, cleanup} — implemented as follows today: one HarnessAdapter per installed harness — five planned (claude-code, codex, grok, hermes, openclaw), of which claude-code and codex are built in the PoC-A slice and the other three are deferred — each rendering a definition into that harness's own flags or prepared directory; and exactly one CoordinationSubstrate implementation, a ClawTeam adapter over the ClawTeam *CLI* (pinned 0.3.0@0119833, `mcp<2`, subprocess backend, no tmux, never `launch`, never `--task` through `spawn`, `skip_permissions=false`), plus a trivial `direct` launcher (own subprocess, file-delivered prompts, no DAG) for solo runs and ensemble legs. The HarnessBroker runs inside this layer as a library/CLI called by the run layer and by the `direct` launcher — not as a ClawTeam backend or plugin; gated operations (`member add`, `nest`, `result`) are CLI commands the Lead calls. It builds no second team substrate, no ClawTeam fork, no library-seam coupling, no Surface adapter, no artifact installer, no UI, no message bus, no task store, no liveness registry. ClawTeam supplies the task DAG, inboxes, pid registry, worktrees and snapshot; the harnesses supply execution. Size: **M (≈4–6k LOC including profile data) with the PoC-A slice ≈2–3k** — schemas + overlay resolver + claude-code and codex adapters + broker resolve/record + `direct` launcher/wrapper + ledger + Ensemble record; the run layer is gated on PoC A passing; operational mode and the Proposal generator come after PoC C.

## 2. Common setup

**Must exist on the host.** Ubuntu 20.04 / Linux 5.15, no tmux — the team path is ClawTeam's subprocess backend plus the `direct` launcher [ev:clawteam-probe-log#F12][ev:clawteam-probe-log#F15]; Claude Code 2.1.239 and Codex 0.148.0 on PATH; for PoC B/C a uv CPython 3.11 venv with ClawTeam 0.3.0@0119833 and `mcp<2` [ev:clawteam-probe-log#F1] (`clawteam` CLI only, never `clawteam-mcp`); Hermes 0.20.4 only if Q6 = yes; Grok and OpenClaw are required by no PoC; no OpenClaw Gateway, no Telegram (product-intent §4; [fitgap:MS-01]). Credentials by env name only (AR-04), per Q5 — `claude --bare` never reads OAuth, so an `ANTHROPIC_API_KEY` or `setup-token` is a hard prerequisite [ev:harness-cli-capabilities-a#F15].

**Created throwaway under one root `$POC`.** `definitions/` (the Assistants and TeamTemplate under test, `git init`-ed so `git status --porcelain` is a second unchanged check); `fixture*/` target repos; `runs/<run-id>/` (`run.json`, per-Member workspaces, rendered bundles, teed stdout/stderr); `ledger/` (HarnessInvocation + Ensemble records); per-harness throwaway state `CLAUDE_CONFIG_DIR=$POC/state/claude`, `CODEX_HOME=$POC/state/codex`, a cloned Hermes profile under `$POC/state/hermes` [ev:harness-cli-capabilities-a#F19][ev:harness-cli-capabilities-b#F19]; for ClawTeam `HOME=$POC/state/ct-home` (its `config.json` is always `~/.clawteam/config.json` [ev:clawteam-model#F2]) with `default_backend: subprocess`, `skip_permissions: false`, and `CLAWTEAM_DATA_DIR` per run or shared (§5) [ev:clawteam-probe-log#F3].

**Never touched.** `~/.clawteam`, `~/.claude`, `~/.codex`, `~/.hermes`, `~/.openclaw`, `~/.grok`; the reference checkouts under `/home/wsh/Documents/00000/`; this repository's `docs/`. A fail-closed guard runs before the first subprocess of each PoC: every state variable must resolve under `$POC`, else abort — ATM's disposable-profile practice, kept as practice not code [model:legacy-atm-disposition#2][ev:atm-salvage#F20]; after each PoC a newer-than-start scan of the production dirs must be empty (R6 [model:legacy-atm-disposition#4]).

**"Definition unchanged" assertion.** `defhash` = SHA-256 over sorted relative paths and bytes of `$POC/definitions/` (modes excluded), snapshotted before the first invocation, after every run and after cleanup; PASS requires all snapshots equal and `git status --porcelain` empty. Bundles are therefore copies — never symlinks into `definitions/` — the AT-13 precedent [ev:atm-salvage#F19][model:assistant-domain-model#4].

**How HarnessInvocations are recorded.** One JSON record per invocation in the shape of [model:harness-broker-model#7]: `invocation_id, run_id, member, ensemble_id, assistant_ref{id, version, effective_hash}, backend{name, version from --version}, selection{decided_by, candidates}, injection{bundle_id, bundle_hash, render{part→channel}, degraded[]}, command{argv_redacted, cwd, env_names, launcher}, harness_session{id}, timing, usage{tokens, cost_usd, cost_source}, outcome{status, exit_code}, artifacts[], output_ref`. Opened with `status: started` before the process starts and closed on exit, so an aborted invocation still leaves a terminal record (ATM R4 [model:legacy-atm-disposition#4]). The wrapper (`direct`, or `ats-wrap` under ClawTeam) tees stdout/stderr and captures the exit code, because ClawTeam discards both and journals `exit_code: null` [ev:clawteam-spawn-platform#F21][ev:clawteam-probe-log#F14][reuse:G-TE-07]. Fields per harness: Claude `--output-format json` → `session_id`, `total_cost_usd`, `modelUsage`; Codex `--json` → `thread.started`, token counts, no USD (`cost_source: unavailable|derived`, Q9) [ev:harness-cli-capabilities-a#F10]; Hermes `-z --usage-file` [ev:harness-cli-capabilities-b#F7].

**Two tiers.** Tier 0: a deterministic no-op "harness" script that accepts the rendered argv, echoes `bundle_hash`, writes schema-valid canned output and exits as instructed — plumbing, records and hashes at zero cost (ATM R11; [panel:judge-2.md#7]). Tier 1: the real harnesses. Only Tier 1 can PASS (product-intent §4 demands real reviews and a completed task); Tier 0 is a precondition unless Q8 says otherwise.

**Day-one probes (preconditions; [model:architecture-options#5] assumption (j)).** (a) `codex exec -c developer_instructions=…` honoured on 0.148.0 and a positional prompt without a TTY [ev:harness-cli-capabilities-a#F2][ev:clawteam-spawn-platform#F1]; (b) `claude -p --bare --append-system-prompt-file` under the wrapper — the flag is in docs and binary but not in `--help` [ev:harness-cli-capabilities-a#F2]; (c) Hermes `--source tool` hiding and memory writes on 0.20.4 iff Q6 = yes [ev:harness-cli-capabilities-b#F6]; (d) one Windows and one macOS smoke (§6).

## 3. PoC A — reusable Assistant, interchangeable harness

**Substrate.** The `direct` launcher; no ClawTeam team, no DAG. **Definition under test.** `code-reviewer` per [model:assistant-domain-model#3]: `persona.md`, `principles.md`, `skills: [code-review]` (one vendored SKILL.md), `permissions {filesystem: read-only, network: deny, shell: allow}`, `harness_policy {preferred: [codex, claude-code], requires_capabilities: [headless, structured_output]}`, `preferences.output: findings by severity`. No User Overlay; user-level overrides arrive only as run flags (below).

**Inputs (fixed).** `$POC/fixture-a/`: a throwaway git repo (small Python package with tests) whose last commit plants three defects (an off-by-one, an unsafe shell call, a behaviour change without a test); target = `target.diff` (`git diff base..head`) plus the checkout at `head`; `target_sha256` recorded. Each invocation gets its own workspace copy. Identical positional task text for every run: "Review `target.diff` in this workspace; answer per the schema." Review schema: `{target_sha256, findings[]{id, severity, file, line?, title, rationale}, summary, verdict}`. Synthesis schema: `{inputs[], agreements[]{title, sources[]}, disagreements[]{title, asserted_by[], not_asserted_by[], severity_conflict?}, merged_findings[]}` with `sources`/`asserted_by` holding invocation ids.

**Injection per harness** (definition-injection matrix [model:harness-broker-model#4][ev:harness-cli-capabilities-a#F17]). The bundle — system text (persona + principles + collaboration), skills dir, permission intent, output schema — is rendered once and hashed (`bundle_hash`), then rendered into channels:

| Part | Run 1 — Codex 0.148.0 | Run 2 — Claude Code 2.1.239 |
|---|---|---|
| persona, principles, collaboration | `-c developer_instructions=<text>` (observed; probe (a)); fallback `$CODEX_HOME/AGENTS.md` → `degraded: [system-prompt-as-file]` | `--append-system-prompt-file <bundle/system.md>` (probe (b)); fallback `--append-system-prompt <text>` |
| skills | copied to `<ws>/.agents/skills/code-review/` | `--add-dir <bundle>` containing `.claude/skills/code-review/` |
| permissions | `-s read-only -a never` | `--permission-mode dontAsk --allowedTools Read,Grep,Glob,Bash(git diff*)` (illustrative) |
| isolation (TE-02) | `--ephemeral --ignore-user-config`, `CODEX_HOME=$POC/state/codex` | `--bare --no-session-persistence`, `CLAUDE_CONFIG_DIR=$POC/state/claude` |
| output | `--json --output-schema review.schema.json -o <ws>/review.json -C <ws>` | `--output-format json --json-schema review.schema.json` |
| record | thread id, tokens, `cost_source: unavailable` (or `derived`, Q9), `codex --version` | `session_id`, `total_cost_usd`, `modelUsage` |

**Run shapes.** *Run 1* `ats run --assistant code-reviewer --target $POC/fixture-a` with no user override → the broker resolves the Assistant-level policy → codex, `decided_by: assistant`. *Run 2* with user-level `--harness claude-code` → `decided_by: user` (HB-03 precedence exercised). *Run 3* user-level `--ensemble claude-code,codex`: two legs sharing one `bundle_id`, each in its own workspace and state dir, run independently (no shared files, no message edge); then a third recorded invocation — the synthesis — whose prompt carries both `review.json` labelled by invocation id and whose schema is the synthesis schema; legs carry `ensemble_id`, the synthesis carries `inputs: [leg ids]` [model:harness-broker-model#8]. `synthesis_harness` defaults to claude-code (structured output + reported cost) until Q9 is answered; the choice and its bias are recorded in the Ensemble record.

**Success criteria** (product-intent §4 verbatim → measurable check).
1. "the definition file is byte-identical before and after all three runs" → `defhash` equal at all five snapshots; `git status --porcelain` empty.
2. "each run produces a review of the same target" → `review.json` validates for Run 1, Run 2 and both Run 3 legs; each `target_sha256` equals the fixture's.
3. "Run 3's synthesis lists agreements and disagreements with per-harness attribution" → synthesis output validates; every `sources`/`asserted_by` id resolves to a ledger record naming harness + version; `agreements[]` non-empty and `disagreements[]` non-empty or an explicit recorded "none".
4. "each HarnessInvocation is recorded" → exactly five closed records (Run 1, Run 2, leg a, leg b, synthesis), each with terminal status, non-null exit code, `decided_by`, teed output, and — decisive — the same `bundle_hash` on Run 1, Run 2 and both legs: the proof that different channels carried one definition [model:harness-broker-model#4].
Informational: planted-defect recall; Codex `degraded[]`.

**Proves / falsifies.** PASS proves AD-04, AD-08, HB-02 (two harnesses), HB-03, HB-05, HB-07 on the PoC-A slice. FALSIFIED if no channel reaches Codex without editing the definition (both `-c` and `AGENTS.md` fail — HB-02 [fitgap:HB-02]); if any harness writes into `definitions/` (AD-05 enforcement); if the synthesis cannot attribute (HB-05/HB-07).

**Cost/time bound.** Tier 1 = five invocations over a ≤300-line diff; `--max-budget-usd 2` per Claude invocation [ev:harness-cli-capabilities-a#F10]; ≤ USD 10 per cycle (estimate), ≤ 3 cycles, ≤ 45 min wall per cycle. Tier 0 is free.

## 4. PoC B — reusable Team + dynamic hidden Member

**TeamTemplate** `development` {lead: implementation-planner, implementer, reviewer: code-reviewer} per [model:team-execution-model#2], with `dynamic_members {may_create: [lead], max_count: 2, allowed_harnesses: [codex, claude-code]}` (+ hermes iff Q6), `visibility_defaults.dynamic_members: hidden`, `independence: reviewer↔implementer level: advisory` (mechanical is not claimed), `workflow_skeleton` t1 Plan (lead) → t2 Implement (implementer, blocked_by t1) → t3 Review (reviewer, blocked_by t2) → t4 Report (lead, blocked_by t3). Supplied at instantiate: throwaway repo `$POC/fixture-b/` and task "add a `--json` output flag to the CLI, with tests". Harness binding: lead → Claude Code, implementer → Codex, reviewer → Codex, or Hermes `chat --source tool -q … -p <cloned profile>` per Q6 [ev:harness-cli-capabilities-b#F6] — ≥2 harnesses either way. The Lead creates one hidden temporary specialist `testgap` (Ephemeral Assistant: "find and add the tests the implementer missed") on Codex, task t2b `blocked_by t2`.

**Substrate mechanics** (ClawTeam CLI, subprocess backend, no tmux; never `launch`, never `--task`; [model:architecture-options#3] PoC B). Env `CLAWTEAM_DEFAULT_BACKEND=subprocess`, `CLAWTEAM_DATA_DIR=$POC/runs/B/ct`, HOME as §2. (1) `ats run development --repo $POC/fixture-b --task …` writes `run.json` before any process [model:team-execution-model#3]. (2) With the Lead's identity in env, `clawteam team spawn-team run-B --agent-name lead`, so the Lead Member is ClawTeam's leader [ev:clawteam-model#F5] (if spawning name `lead` into that team is then refused, fallback: the Lead's own `spawn` auto-creates the team [ev:clawteam-probe-log#F18] — settled in Tier 0). (3) `clawteam task create run-B … --blocked-by <real id>` for t1..t4, ids validated by the layer since ClawTeam accepts dangling ones [ev:clawteam-probe-log#F7]. (4) Per Member: `clawteam spawn subprocess --team run-B -n <m> [--repo $POC/fixture-b | --no-workspace] --no-keepalive -- ats-wrap <inv-id>` — an explicit positional command, so no implicit profile and no `-p` append because no `--task` is given [ev:clawteam-spawn-platform#F5][ev:clawteam-probe-log#F12]; `ats-wrap` reads the bundle from a file (persona + principles + a coordination section rendered with the exact `clawteam task/inbox` verbs and run id, Q10), launches the harness headless as in §3 with stdin from `/dev/null`, and tees output. Every `spawn` exit fires `lifecycle on-exit` (task reset + "exited unexpectedly" to the ClawTeam leader even on exit 0) — accepted noise, described in the Lead's bundle [ev:clawteam-probe-log#F14]. (5) The Lead runs as one long headless invocation (`--max-turns`, budget cap) and coordinates through `clawteam task update/list`, `inbox send/receive`; mid-run it calls `ats member add --hidden --from-ephemeral $RUN/members/testgap.md --harness codex`; the gate evaluates `dynamic_members` **before** the substrate `spawn`, writes the Ephemeral Assistant into the run directory and records `visibility: hidden, origin: ephemeral, created_by: lead, policy_decision` [model:team-execution-model#5][model:assistant-domain-model#8]; a run-scoped `CLAWTEAM_BIN` shim refuses raw `clawteam spawn` from Members — TC-05 = gate + convention + shim + post-hoc reconciliation [ev:clawteam-spawn-platform#F16][panel:judge-2.md#5]. (6) Completion via `clawteam task wait run-B --agent ats-observer` (explicit `--agent` avoids draining the leader inbox [ev:clawteam-model#F8]) plus registry liveness [ev:clawteam-probe-log#F13]. (7) Archive: `team snapshot run-B`, SIGTERM surviving pids from `spawn_registry.json`, `team cleanup` [ev:clawteam-probe-log#F20].

**Success criteria** (§4 verbatim → check).
1. "the TeamTemplate is unchanged" → `defhash` (template + the three Assistants) equal before/after; git clean.
2. "the run archive shows the hidden member (auditable) while the user-facing member list does not" → archive roster has `testgap {visibility: hidden, origin: ephemeral, created_by, policy_decision, definition_ref}` with its invocation record and teed output, and the reconstruction test (rebuild argv + bundle from the archive alone) succeeds; `ats status` / the visible projection lists exactly lead, implementer, reviewer. Honesty label: ClawTeam's `team status`/`board show` still lists `testgap` — two rosters, accepted for the PoC [ev:clawteam-probe-log#F10][fitgap:TC-04][panel:judge-2.md#5].

4. "at least two members use different harnesses" → ledger `backend.name` differs between lead and implementer; `spawn_registry.json` entries resolve through `ats-wrap` to distinct harness binaries [ev:clawteam-probe-log#F16].

## 5. PoC C — nested TeamRun

**Shape.** Outer TeamRun `ops-lite` on the ClawTeam substrate with one visible Member `codemod` (Assistant `code-modification`, Claude Code) and outer tasks t4 "eliminate the dataloader OOM in `fixture-c`" and t5 "report" (blocked_by t4). CodeMod judges t4 complex and runs `ats nest development --for-task t4`; the inner TeamRun is the PoC B template on mixed harnesses; the result returns; the inner run is archived; the outer run continues to t5.

**Mechanics** (nesting contract [model:team-execution-model#6] items 1–7, on ClawTeam per [model:architecture-options#3] PoC C).
