# Architecture options

> Reading guide. This document ranks options and states the answer; it re-authors no requirement (IDs from `product-intent.md` §3), re-classifies no fit cell (`existing-systems-fit-gap.md`) and re-decides no reuse rung (`reuse-vs-build-analysis.md`). Terminology follows `evidence/glossary.md`; "agent", "leader", "worker" and "session" appear only as ClawTeam's, Claude Code's or OpenClaw's own words. §5 is self-contained so that its paragraph and table can be copied into `README.md` and restated in `minimal-poc-plan.md`.

## 1. Question, method and rubric

**The question.** `product-intent.md` §6 asks discovery to answer one thing: *what is the smallest new software layer that genuinely needs to be built* — given ClawTeam, its OpenClaw fork, OpenClaw, Claude Code, Codex, Grok, Hermes and the reference designs — so that a reviewer can accept or reject it and the project stops for review.

**Rubric R1–R10 (shared by every panel member; 1–5, higher better; size S < 2k LOC, M 2–8k, L > 8k, newly written code only).** R1 new-code size · R2 upstream-merge / dependency risk (ClawTeam internals, fork divergence, unmaintained dependencies — upstream last commit 2026-05-09, `clawteam-mcp` broken by unpinned `mcp` [ev:clawteam-spawn-platform#F24][ev:clawteam-probe-log#F1]) · R3 cross-platform / tmux-free story (no tmux here; subprocess backend; `os.getuid()` bug [ev:clawteam-spawn-platform#F20]) · R4 pressure-test coverage (PoC A, PoC B, PoC C, evolution, long-running operational run, hidden Member audit; clean vs hack vs not at all) · R5 lock-in / reversibility · R6 licence incl. automation-flag/ToS caveats · R7 time-to-PoC on this machine · R8 12-month maintenance · R9 reuse-ladder alignment (XC-03: lowest rung that actually satisfies the M rows) · R10 coverage of M-priority rows, listing any M requirement the option cannot satisfy.

**How proposals and judges were combined.** Three deliberately biased architects each evaluated all eight options on R1–R10 and proposed a "smallest layer": A (ClawTeam maximalist) answered O2 — an `ats` package over the ClawTeam *CLI* [panel:proposal-A-clawteam-maximalist.md#4]; B (independent layer) answered O7 — a Core with two declared seams and several execution backends [panel:proposal-B-independent-layer.md#4]; C (upstream-extension-first) answered O2+O3 over ClawTeam's Python seams with O5 PRs filed [panel:proposal-C-upstream-extension.md#4]. Two judges scored the *architecture each proposal actually proposes* against the evidence, never against the proposals' own text: Judge 1 (requirements and evidence fidelity) gave A 40, B 41, C 31 [panel:judge-1.md#2]; Judge 2 (reuse ladder, cross-platform, lock-in, maintenance) gave A 39, B 37, C 33 [panel:judge-2.md#2]. Both independently endorsed the same named composition — "A's O2 scope with B's two seams declared; C's PR set filed as good citizenship; C's in-process `SpawnBackend` kept only as the documented Windows fallback" [panel:judge-1.md#5][panel:judge-2.md#5]. Where they differed (Judge 1 Q9: smaller *scope* with B's seams, or smaller *LOC claim*?), the owner's tiebreak note of 2026-08-22 is authoritative: quoted in full in §5, its assumptions (a)–(l) adopted verbatim in §3 and §5. Consolidated option scores in §2 are the range across the three architects' option tables, corrected where a judge found the underlying claim false (§4).

**O1 — ClawTeam as-is + reusable Assistant packages (conventions + scripts).** *Shape:* an Assistant is a directory of Markdown; a TeamTemplate is a ClawTeam TOML template whose `AgentDef.task` strings carry the rendered persona and whose per-agent `command` names the harness [ev:clawteam-model#F13][ev:clawteam-probe-log#F16]; the Lead (Claude Code or Codex holding ClawTeam's Skill [ev:clawteam-model#F16]) brokers by reading a policy file and nests by the documented CLI composition [ev:clawteam-model#F22]; up to three scripts (renderer, `tee` wrapper, Hermes shim). *Not built:* any object, record, gate, overlay or Proposal. *tmux-free/Windows:* subprocess backend works here [ev:clawteam-probe-log#F12]; Windows hits `os.getuid()` under the default `skip_permissions`, has no keepalive/exit code, truncates multi-line `-p` prompts in cmd.exe [ev:clawteam-spawn-platform#F20]. *Cannot satisfy (M):* AD-02, AD-05, AD-07, TC-01, TC-05, TE-05 (no parent link/result contract, cleanup leaves processes [ev:clawteam-probe-log#F18][ev:clawteam-probe-log#F20]), TE-07 (DEVNULL, `exit_code: null` [ev:clawteam-spawn-platform#F21][ev:clawteam-probe-log#F14]), HB-01, HB-03 (precedence inverted [ev:clawteam-probe-log#F17]), HB-05 (system prompt dropped for Codex [ev:clawteam-spawn-platform#F6]), EV-02, EV-03, AR-01/02/03 [fitgap:AD-01][fitgap:TC-01][fitgap:HB-01][fitgap:EV-03]. *Ladder:* rung 1 — below the rung that satisfies the M rows [reuse:G-AD-01][fitgap:XC-03]. *Size:* S.

**O2 — ClawTeam + thin Assistant composition layer.** *Shape:* a small package owns the data objects no substrate has (Assistant, TeamTemplate, overlays, HarnessProfiles, policy, run/invocation records, Proposals) and *compiles* a TeamRun into ClawTeam CLI calls — `team spawn-team`, `task create --blocked-by`, per-Member `spawn subprocess … -- <wrapper> <rendered argv>`, `task wait`, `snapshot`, stop, `cleanup` — never `launch` (swallows errors, one profile for all, no DAG edges [ev:clawteam-probe-log#F15][ev:clawteam-probe-log#F23][ev:clawteam-spawn-platform#F12]); an explicit positional command suppresses ClawTeam's implicit profile [ev:clawteam-spawn-platform#F5], so the layer decides how the definition reaches each harness; a wrapper tees output and writes the HarnessInvocation. *Not built:* DAG, mailbox, liveness, worktrees, tmux, Surfaces, a fork, a second team substrate. *tmux-free/Windows:* `skip_permissions=false` in the layer-written config (`os.getuid()` sits inside `if skip_permissions:` [panel:judge-1.md#1]); prompts by file; wrapper-captured exit codes; unprobed off this host [fitgap:TE-08]. *Cannot satisfy:* TE-08 only documented; HB-02 Codex channel observed, not executed [ev:harness-cli-capabilities-a#F2]; TC-05 gate bypassable by a Lead calling `clawteam spawn` directly [ev:clawteam-spawn-platform#F16]; TE-05 isolation namespace-only [ev:clawteam-probe-log#F19]; AR-03 metadata-only. *Ladder:* rung 1/2 over ClawTeam, rung 6 only for the 23 data objects [reuse:G-XC-03]. *Size:* M.

**O3 — ClawTeam + HarnessBroker extension (broker as ClawTeam backend/plugin).** *Shape:* the broker packaged as a custom `SpawnBackend` registered through `register_backend`, receiving `prompt`/`system_prompt`/`command` [ev:clawteam-spawn-platform#F8]. *Not built:* definitions, templates, nesting, evolution. *Why it is a misnomer:* `register_backend` is process-local, `clawteam spawn` never loads plugins, and `BeforeWorkerSpawn` neither fires on the CLI paths nor can mutate [ev:clawteam-spawn-platform#F16][ev:clawteam-spawn-platform#F17] — so the entry point must be our own process importing "Alpha" seams with no `__all__` [ev:clawteam-spawn-platform#F15]; and ClawTeam's `is_agent_alive`/`stop_agent` handle only `tmux|subprocess|wsh` names, so a custom backend is never seen alive or dead and its task locks are never releasable [panel:judge-1.md#1][ev:clawteam-probe-log#F8]. The broker is part of the layer, not a ClawTeam backend. *Windows:* an in-process backend never calls `prepare_command` — no `os.getuid()`, no argv prompt — the one genuine advantage, Python-only. *Cannot satisfy alone:* AD, TC, TE-05, EV, AR M rows. *Ladder:* rung 2/3 on the least stable seam where the CLI seam satisfies the same rows. *Size:* M.

**O4 — ClawTeam + optional OpenClaw/Telegram Surface.** *Shape:* O1/O2 unchanged plus a Surface adapter presenting a TeamRun's *visible* Members over OpenClaw channels (`agent --deliver`, bindings, `identity`) or Hermes `send --to` [ev:openclaw-native-and-telegram-verification#F20][ev:claude-agent-teams-hermes-openbot#F26]. *Not built:* anything that closes an M gap. *Windows:* Gateway daemon per host; WSL2 recommended [ev:harness-cli-capabilities-b#F16]. *Cannot satisfy:* whatever its core cannot; MS-01/MS-04 are already satisfied without it [fitgap:MS-01][fitgap:MS-04]; MS-02 is C-priority; the PoCs need neither OpenClaw nor Telegram (product-intent §4). *Ladder:* rung 2 for a C row. *Size:* S adapter plus two daemons' release trains and OpenClaw flag drift [ev:clawteam-openclaw-fork-delta#F5].

**O5 — upstream ClawTeam extensions (PRs only).** *Shape:* the nine bounded PRs of [reuse:§5] (enumerated under "Deferred" in §5; the pre-spawn mutation hook was dropped by C itself once the broker renders before spawn). *Not built:* our objects. *Windows:* the guard/logs PRs are exactly the Windows fixes, if merged. *Cannot satisfy:* every object O1 lacks; and R2 = 1 — HEAD `0119833` unchanged since 2026-05-09, 22 open PRs, #82/#88 open since 2026-03-24, #159/#165/#167 unanswered (re-verified by both judges on 2026-08-22) [ev:clawteam-spawn-platform#F24][panel:judge-1.md#1]. *Ladder:* rung 3, which "is never the only path" — every item has a rung-2 shadow [reuse:G-XC-03]. *Size:* S (~0.4–0.7k incl. tests).

**O6 — selective reuse of existing modules into a new small layer.** Two readings exist in the panel. *Reading 1 (A):* vendor ClawTeam's task store/mailbox/registry and *replace* ClawTeam — M–L, rung 4 where rung 1–2 satisfies TE [fitgap:TE-01]. *Reading 2 (B, C, adopted here):* a sourcing rule, not a layer — vendor the fork's stdlib-only `platform_compat.py` (130 lines), `model_resolution.py` (70 lines, precedence pattern) and `spawn_with_retry` (25), attributing HKUDS (MIT, no SPDX headers in fork-only files) [ev:clawteam-openclaw-fork-delta#F19][ev:clawteam-openclaw-fork-delta#F28][ev:clawteam-openclaw-fork-delta#F30]; take Hermes `distribution.yaml`, DG `.strict()` schemas and ATM ADR 0022 as *patterns* (ATM text blocked until licensed [reuse:§7]). *Windows:* `platform_compat` is the shim. *Cannot satisfy alone:* it needs O2/O7 to say what the layer is. *Ladder:* rung 4 exactly where it is cheapest (TE-08 shims, HB-03 pattern, AR-03 shape). *Size:* S vendored.

**O7 — a small independent Assistant/Harness layer above multiple execution backends.** *Shape:* O2's objects plus two seams (HarnessAdapter; CoordinationSubstrate) and several backends: ClawTeam, direct CLI, Claude Code native subagents/teams, OpenClaw sessions, Hermes kanban [panel:proposal-B-independent-layer.md#4]. *Not built:* DAG, mailbox, liveness, UI, Surfaces. *Windows:* the `direct` launcher (own `subprocess`, `shell=False`, file-delivered prompts) is the cleanest tmux-free path for solo runs and ensemble legs. *The evidence on the extra backends:* Claude Code teams are experimental, Claude-only, interactive-only, non-nested [ev:claude-agent-teams-hermes-openbot#F2][ev:claude-agent-teams-hermes-openbot#F6][ev:claude-agent-teams-hermes-openbot#F7][ev:claude-agent-teams-hermes-openbot#F8]; OpenClaw `sessions_spawn(runtime:"acp")` needs the Gateway and the absent acpx plugin and gives ACP children prompt + cwd only [ev:openclaw-native-and-telegram-verification#F16][ev:harness-cli-capabilities-b#F12]; Hermes kanban is Hermes-only and un-nestable [ev:claude-agent-teams-hermes-openbot#F25]. None can host a mixed-harness nested TeamRun today [fitgap:TE-03][fitgap:TE-05]; B concedes "multiple backends is thinner than the slogan" [panel:proposal-B-independent-layer.md#8]. *Cannot satisfy:* TE-08 docs-only; HB-02 Codex; AD-05/EV-04 heuristic. *Ladder:* rung 2 + 6 like O2, plus a seam built before a second team substrate exists (XC-03 bent, not broken). *Size:* M–L (B's table sums ≈11.6k; most of the excess is scope the register does not demand [panel:judge-1.md#3]).

**O8 — a new implementation.** *Shape:* own DAG, mailbox, registry, spawn, archive. *Why not:* the TE layer is "not genuinely new — reachable at reuse rung 1–3" [fitgap:TE-01]; ClawTeam's DAG/inbox/registry are `S!` probe-verified [ev:clawteam-probe-log#F7][ev:clawteam-probe-log#F9][ev:clawteam-probe-log#F13]; ATM's lesson: "do not build a mailbox runtime" [ev:atm-salvage#F22]. *Ladder:* rung 6 with rung 1–2 available — violates XC-03. *Size:* L; months to a PoC.

**Ranking (owner tiebreak, adopted):** O2 + seams (the composition of §5) > O7 (B) > O5 filed-not-depended-on > O6 selective vendoring (`platform_compat.py`, `model_resolution.py` pattern, attribute HKUDS) > O3 (misnomer: the broker is part of the layer, not a ClawTeam backend) > O1 (fails M rows EV-03, AD-05, TC-05, TE-05, HB-01/03) > O4 > O8 (not justified by evidence).

## 3. Pressure-test walkthroughs under the recommended layer

All eight walk on the composition of §5 (mechanics → new vs reused → evidence) under the owner's assumptions: (b) the layer never passes `--task` through `clawteam spawn` — the wrapper delivers the whole bundle (persona, principles, coordination section) from a file and `skip_permissions=false` is written into the layer's ClawTeam config, so no multi-line prompt transits argv on any OS (ClawTeam builds its prompt only when `task` is given and the generic adapter branch appends `-p` only `elif prompt:` [panel:judge-1.md#1][ev:clawteam-probe-log#F12]); (c) every `clawteam spawn subprocess` exit, clean or not, runs `lifecycle on-exit` (task reset + "exited unexpectedly" to the ClawTeam leader; `--no-keepalive` does not suppress it) [ev:clawteam-probe-log#F14][panel:judge-1.md#1], so one-shot legs use the `direct` launcher and register nothing in ClawTeam; (g) ClawTeam state is read through CLI `--json` and `team snapshot`; the only internal file read is `spawn_registry.json` (pids for stop-before-cleanup) [ev:clawteam-probe-log#F13][ev:clawteam-probe-log#F20].

**PoC A — same Assistant on Codex / Claude Code / both + synthesis.** *Mechanics:* `ats run --assistant code-reviewer --harness codex` on the `direct` launcher (no ClawTeam team). The overlay resolver produces the effective definition + hash; the HarnessBroker resolves policy (user > Assistant > team > default, deciding layer recorded) and prepares one injection bundle (persona + principles text, skills dir, permission intent, output schema) with `bundle_hash`; the codex adapter renders `codex exec -c developer_instructions=<text> --json --output-schema review.json -C <ws> --ephemeral`, the `AGENTS.md`-in-`CODEX_HOME` fallback recorded as `degraded[]` [ev:harness-cli-capabilities-a#F2][ev:harness-cli-capabilities-a#F17]; Run 2 renders `claude -p --bare --append-system-prompt-file <bundle> --output-format json --json-schema review.json` [ev:harness-cli-capabilities-a#F19][ev:harness-cli-capabilities-a#F10]; the wrapper tees output, captures the exit code, parses `session_id`/`total_cost_usd` (Claude) or tokens only (Codex, `cost_source: unavailable|derived`, assumption (l)) and writes the HarnessInvocation [model:harness-broker-model#7]. Run 3 is an Ensemble record: two legs sharing `bundle_id`, each in its own workspace with its profile's isolation knobs, then a third recorded invocation whose prompt carries both structured outputs labelled by invocation id and whose schema requires `agreements[]/disagreements[]` with source ids [model:harness-broker-model#8]. Pass check = hash of the definition directory before and after. *New:* schemas + validator, resolver, profiles/policy, two adapters, broker, wrapper, ledger, Ensemble record. *Reused:* every harness flag. *Preconditions:* the Codex and Claude day-one probes of assumption (j) [fitgap:HB-02].

**PoC B — fresh TeamRun, hidden temporary Member, mixed harnesses.** *Mechanics:* `ats run development --repo R --task T` → the run layer resolves three Assistants, the broker binds a harness per Member, `run.json` is written before any process starts [model:team-execution-model#3]; the ClawTeam adapter (`CLAWTEAM_DEFAULT_BACKEND=subprocess`, optional per-run `CLAWTEAM_DATA_DIR` [ev:clawteam-probe-log#F3]) runs `team spawn-team run-X -n lead` first (the first spawn into a new team becomes ClawTeam's leader [ev:clawteam-model#F5]), `task create --blocked-by` from the workflow skeleton (ids validated by the layer [ev:clawteam-probe-log#F7]), then per Member `spawn subprocess --team run-X -n <m> -- ats-wrap <invocation>` with fully rendered argv (Lead on Claude Code, Implementer on Codex, Reviewer on Codex or Hermes `chat --source tool -q … -p <cloned profile>` [ev:harness-cli-capabilities-b#F6][ev:harness-cli-capabilities-b#F19]; per-Member command by configuration is probe-verified [ev:clawteam-probe-log#F16]). Mid-run the Lead calls `ats member add --hidden --from-ephemeral migsafe.md`; the gate checks `dynamic_members {may_create, max_count, allowed_harnesses}` *before* the substrate spawn, writes the Ephemeral Assistant into the run directory and records `visibility: hidden, origin: ephemeral, policy_decision` [model:team-execution-model#5]. `ats status` filters hidden, `ats archive` lists all; completion via `task wait run-X --agent <observer>` (explicit `--agent` avoids draining the leader inbox [ev:clawteam-model#F8]). *New:* run record, roster projections, gate, Ephemeral Assistant writer, wrapper. *Reused:* ClawTeam team/task/inbox/registry/snapshot. *Honesty (assumptions (d), (f)):* two rosters — ClawTeam's `team status`/`board show` still list `migsafe` [ev:clawteam-probe-log#F10], so PoC B's "user-facing member list" is the layer's view; TC-05 is "gate + convention + run-scoped `CLAWTEAM_BIN` shim + post-hoc reconciliation of `spawn_registry.json` against the roster" until enforced [ev:clawteam-spawn-platform#F16].

**PoC C — nested TeamRun.** *Mechanics:* CodeMod, a Member of `ops`, runs `ats nest development --for-task t4`; the run layer checks `nesting {allowed, max_depth}`, creates inner run `run-c21d` with `parent {run_id: ops, member: codemod, task_id: t4}`, `depth: 1`, its own run directory and a ClawTeam team named by run id, created with `team spawn-team run-c21d -n codemod` **first** so the creating Member — not the first child — is ClawTeam's leader (trap 1 [ev:clawteam-probe-log#F18]); inner Members get inner identity (`ATS_RUN_ID`), fresh contexts (`--bare`, cloned profiles) and worktrees based on t4's branch [ev:clawteam-probe-log#F22]; outer `t4` is marked `delegated_to`; waiting uses `task wait run-c21d --agent codemod` (trap 2 [ev:clawteam-model#F8]) plus registry liveness. *Isolation (assumption (e)):* ClawTeam enforces no inter-team boundary [ev:clawteam-probe-log#F19]; the run records `independence.achieved: namespace` (shared data dir), `data-dir` (per-run `CLAWTEAM_DATA_DIR`, still bypassable by the global `--data-dir` flag [ev:clawteam-probe-log#F2]) or `mechanical` (inbox-ACL PR merged or spawn path owned); whether per-run data dirs break the creating Member's `task wait`/inbox discovery is settled on the first PoC C run [model:team-execution-model#13]. *New:* nesting contract. *Reused:* ClawTeam team-as-namespace, snapshot [ev:clawteam-model#F22].

**Nested TeamRun result + archive.** *Mechanics:* the inner Lead ends with `ats result --status completed --summary … --deliverables … --risks …`; the run layer writes RunResult into the inner `run.json`, then delivers it by **both** carriers — `clawteam task update ops t4 --metadata` (record; unverified with real agents, probe open question 3 [ev:clawteam-probe-log#F20]) **and** `clawteam inbox send ops codemod` (notification; cross-team send probe-verified [ev:clawteam-probe-log#F19]) — settling which is reliable in PoC C (assumption (e)); `team snapshot run-c21d` (survives cleanup [ev:clawteam-model#F22]); SIGTERM the inner pids from `spawn_registry.json` because `team cleanup` deletes data but not processes [ev:clawteam-probe-log#F20]; `team cleanup`; the outer archive gets `nested_runs[] {run_id, archive_ref}`. Failure: inner Lead dead with tasks pending (registry liveness on ClawTeam's own `subprocess` backend name, never a custom name [panel:judge-1.md#5]) → inner `aborted`, outer `t4 failed` + message. Leak check: definitions directory hash unchanged; inner Ephemeral Assistants stay in the inner archive; inner invocations use `--bare`/`--ephemeral`/fresh profile so harness auto-memory carries no run facts (EV-04) [ev:harness-cli-capabilities-a#F19]. *New:* RunResult contract, stop-before-cleanup, archive linking. *Reused:* `task update --metadata`, `inbox send`, snapshot.

**Ensemble + synthesis (generalised).** *Mechanics:* `ensemble {legs: [claude-code, codex], min_legs: 2, synthesis_harness: policy}` on any Member/task; each leg a HarnessInvocation with `ensemble_id`, own workspace and its profile's isolation knobs; synthesis a recorded third invocation with `inputs: [leg ids]` [model:harness-broker-model#8]. Legs run on `direct` (ClawTeam fan-out is probe-verified [ev:clawteam-probe-log#F16] but every spawn would trigger on-exit noise, assumption (c)). Attribution comes from the ledger, never from ClawTeam's self-reported `CostEvent` [ev:clawteam-model#F28][fitgap:HB-05][fitgap:HB-07]. *New:* Ensemble record, bundle identity, structured verdict, `cost_source` per leg. *Reused:* per-harness output schemas [ev:harness-cli-capabilities-a#F10].

**Evolution overlays + Proposals.** *Mechanics:* `ats propose --from run-…` (after PoC C, assumption (i)) reads archives (findings, Lead corrections, invocation outcomes) and emits bounded, typed Proposals with provenance, `independence_check` (paths, branches, session ids, topics, secrets) and dedupe; `ats review` accepts/rejects, appending to the Reviewed Evolution Overlay with `from_proposal`, `runs`, `approved {by, at, applied_hash}`; the resolver's merge Base → Reviewed Evolution → User changes the effective-definition hash that every later invocation records; `persona/purpose` edits and permission widening are rejected by the per-field policy [model:assistant-domain-model#9]. *New:* overlay document, Proposal + decision record, merge policy, resolver — all data-level; no substrate has any [fitgap:EV-02][fitgap:EV-03]. *Reused:* nothing executable; ClawTeam's plan round-trip is an optional approval transport [ev:clawteam-model#F17]. Only the resolver is in the PoC-A slice.

**Long-running operational run with deterministic backends.** *Mechanics (post-PoC, S-priority):* `TeamRun.mode: operational` with `watchers[] {kind, config, schedule|event, trigger_rules, on_trigger}` registered as deterministic Backends (`BackendProfile{kind: deterministic}`, invocation records without model/cost [model:harness-broker-model#9]); the scheduler substrate is an OS timer (cron / launchd / schtasks) calling `ats tick <run>`, with OpenClaw or Hermes cron pluggable where that daemon already runs, never prerequisites [ev:openclaw-native-and-telegram-verification#F9][fitgap:MS-01]; a fired rule invokes Run & Monitor **fresh** (`--bare`, new session key) with a deterministic RunStateSummary and logs trigger → invocation → decision → action [model:team-execution-model#7]. ClawTeam's resident Worker Loop is the inverse of this mode [ev:clawteam-model#F15][ev:clawteam-model#F18]; operational invocations go through `direct`; ClawTeam holds tasks/messages only. *New:* watcher registry, tick evaluator, summary, decision log. *Reused:* OS schedulers.

**Ephemeral hidden Member audit.** *Mechanics:* the archive roster entry `{name, origin: ephemeral, visibility: hidden, created_by, policy_decision, definition_ref (full rendered text), invocation}`; the invocation record `argv_redacted, cwd, env_names, bundle_hash, stdout path, harness session id, usage, exit code` (the wrapper tees — ClawTeam alone discards output and writes `exit_code: null` [ev:clawteam-spawn-platform#F21][ev:clawteam-probe-log#F14]); ClawTeam's `spawn_registry.json` (pid, argv) and `events/` mirror are referenced [ev:clawteam-probe-log#F13][ev:clawteam-probe-log#F9]. ## 5. The answer

> Owner tiebreak (2026-08-22): both judges independently endorsed the same named composition ("A's O2 scope with B's two seams"); the session owner confirmed it and fixed assumptions (a)–(l) listed in §4; the full note is preserved at `evidence/panel/owner-tiebreak.md`.

**The smallest new software layer is** a thin, format-independent Assistant/Team layer — working name `ats` — that owns only the data no existing system has and reaches everything else through two declared seams with one implementation each. It owns, as substrate-neutral data: Assistant definitions (closed schema + exclusion validator), TeamTemplates composing Assistants by reference, Base/User/Reviewed-Evolution overlays with a deterministic resolver and a Proposal/review record, HarnessProfiles as data plus a HarnessSelectionPolicy resolved per invocation (user > Assistant > team > default), a HarnessInvocation ledger and an Ensemble synthesis record with per-invocation attribution, an artifact manifest + lock + per-host resolution report, and a TeamRun record with two roster projections (user-visible vs archive), a dynamic-member gate, a nesting contract (parent link, result carrier, isolation level recorded, stop-before-cleanup) and an archive. It declares exactly two seams — **HarnessAdapter** {profile data, injection recipe, invoke, parse} and **CoordinationSubstrate** {create_space, add_member, create/update/wait task, send/receive, snapshot, stop, cleanup} — implemented as follows today: one HarnessAdapter per installed harness — five planned (claude-code, codex, grok, hermes, openclaw), of which claude-code and codex are built in the PoC-A slice and the other three are deferred — each rendering a definition into that harness's own flags or prepared directory; and exactly one CoordinationSubstrate implementation, a ClawTeam adapter over the ClawTeam *CLI* (pinned 0.3.0@0119833, `mcp<2`, subprocess backend, no tmux, never `launch`, never `--task` through `spawn`, `skip_permissions=false`), plus a trivial `direct` launcher (own subprocess, file-delivered prompts, no DAG) for solo runs and ensemble legs.
