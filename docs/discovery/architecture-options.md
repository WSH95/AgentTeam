# Architecture options

> Reading guide. This document ranks options and states the answer; it re-authors no requirement (IDs from `product-intent.md` §3), re-classifies no fit cell (`existing-systems-fit-gap.md`) and re-decides no reuse rung (`reuse-vs-build-analysis.md`). Terminology follows `evidence/glossary.md`; "agent", "leader", "worker" and "session" appear only as ClawTeam's, Claude Code's or OpenClaw's own words. §5 is self-contained so that its paragraph and table can be copied into `README.md` and restated in `minimal-poc-plan.md`. Authority: the owner's decisions are the assumptions (a)–(l) enumerated verbatim in §5.0 (complete note at `evidence/panel/owner-tiebreak.md`); everything else in this document is synthesis-authored and is labelled so where the two meet.

## 1. Question, method and rubric

**The question.** `product-intent.md` §6 asks discovery to answer one thing: *what is the smallest new software layer that genuinely needs to be built* — given ClawTeam, its OpenClaw fork, OpenClaw, Claude Code, Codex, Grok, Hermes and the reference designs — so that a reviewer can accept or reject it and the project stops for review.

**Installed versions every option is judged against (this host, 2026-08-21/22).** Claude Code 2.1.239, Codex CLI 0.148.0, Grok CLI 1.0.5 [ev:harness-cli-capabilities-a#F14]; OpenClaw 2026.7.1-2 [ev:harness-cli-capabilities-b#F2]; Hermes 0.20.4 [ev:harness-cli-capabilities-b#F6]; ClawTeam 0.3.0 at upstream HEAD `0119833` (2026-05-09), `mcp<2` [ev:clawteam-spawn-platform#F24][ev:clawteam-probe-log#F1]. §3 and §5 refer to these pins; any version bump re-runs the adapter smoke test (§5 Deferred).

**Rubric R1–R10 (shared by every panel member; 1–5, higher better; size S < 2k LOC, M 2–8k, L > 8k, newly written code only).** R1 new-code size · R2 upstream-merge / dependency risk (ClawTeam internals, fork divergence, unmaintained dependencies — upstream last commit 2026-05-09, `clawteam-mcp` broken by unpinned `mcp` [ev:clawteam-spawn-platform#F24][ev:clawteam-probe-log#F1]) · R3 cross-platform / tmux-free story (no tmux here; subprocess backend; `os.getuid()` bug [ev:clawteam-spawn-platform#F20]) · R4 pressure-test coverage (PoC A, PoC B, PoC C, evolution, long-running operational run, hidden Member audit; clean vs hack vs not at all) · R5 lock-in / reversibility · R6 licence incl. automation-flag/ToS caveats · R7 time-to-PoC on this machine · R8 12-month maintenance · R9 reuse-ladder alignment (XC-03: lowest rung that actually satisfies the M rows) · R10 coverage of M-priority rows, listing any M requirement the option cannot satisfy.

**How proposals and judges were combined.** Three deliberately biased architects each evaluated all eight options on R1–R10 and proposed a "smallest layer": A (ClawTeam maximalist) answered O2 — an `ats` package over the ClawTeam *CLI* [panel:proposal-A-clawteam-maximalist.md#4]; B (independent layer) answered O7 — a Core with two declared seams and several execution backends [panel:proposal-B-independent-layer.md#4]; C (upstream-extension-first) answered O2+O3 over ClawTeam's Python seams with O5 PRs filed [panel:proposal-C-upstream-extension.md#4]. Two judges scored the *architecture each proposal actually proposes* against the evidence, never against the proposals' own text: Judge 1 (requirements and evidence fidelity) gave A 40, B 41, C 31 [panel:judge-1.md#2]; Judge 2 (reuse ladder, cross-platform, lock-in, maintenance) gave A 39, B 37, C 33 [panel:judge-2.md#2]. Each independently endorsed a named composition: Judge 1 — "B's ownership model and two seams, built at A's scope, with C's caveats and C's PRs as optional accelerators" [panel:judge-1.md#5]; Judge 2 — "A's O2 scope with B's two seams declared; C's PR set filed as good citizenship; C's in-process SpawnBackend kept as the documented Windows fallback" [panel:judge-2.md#5]. The overlap — A's scope, B's two seams, C's PRs filed not depended on, ClawTeam-CLI as the only team substrate — is the composition the owner adopted; the in-process fallback is Judge 2's wording, which Judge 1 raises only in dissent [panel:judge-1.md#6]. Where the judges differed (Judge 1 Q9: smaller *scope* with B's seams, or smaller *LOC claim*?), the owner's tiebreak note of 2026-08-22 is authoritative: its ranking is in §2, its assumptions (a)–(l) are enumerated verbatim in §5.0 and adopted in §3 and §5, and the complete note is preserved at `evidence/panel/owner-tiebreak.md`. Consolidated option scores in §2 are the range across the three architects' option tables, corrected where a judge found the underlying claim false (§4).

**O1 — ClawTeam as-is + reusable Assistant packages (conventions + scripts).** *Shape:* an Assistant is a directory of Markdown; a TeamTemplate is a ClawTeam TOML template whose `AgentDef.task` strings carry the rendered persona and whose per-agent `command` names the harness [ev:clawteam-model#F13][ev:clawteam-probe-log#F16]; the Lead (Claude Code or Codex holding ClawTeam's Skill [ev:clawteam-model#F16]) brokers by reading a policy file and nests by the documented CLI composition [ev:clawteam-model#F22]; up to three scripts (renderer, `tee` wrapper, Hermes shim). *Not built:* any object, record, gate, overlay or Proposal. *tmux-free/Windows:* subprocess backend works here [ev:clawteam-probe-log#F12]; Windows hits `os.getuid()` under the default `skip_permissions`, has no keepalive/exit code, truncates multi-line `-p` prompts in cmd.exe [ev:clawteam-spawn-platform#F20]. *Cannot satisfy (M):* AD-02, AD-05, AD-07, TC-01, TC-05, TE-05 (no parent link/result contract, cleanup leaves processes [ev:clawteam-probe-log#F18][ev:clawteam-probe-log#F20]), TE-07 (DEVNULL, `exit_code: null` [ev:clawteam-spawn-platform#F21][ev:clawteam-probe-log#F14]), HB-01, HB-03 (precedence inverted [ev:clawteam-probe-log#F17]), HB-05 (system prompt dropped for Codex [ev:clawteam-spawn-platform#F6]), EV-02, EV-03, AR-01/02/03 [fitgap:AD-01][fitgap:TC-01][fitgap:TE-05][fitgap:TE-07][fitgap:HB-01][fitgap:EV-03][fitgap:AR-01]. *Ladder:* rung 1 — below the rung that satisfies the M rows [reuse:G-AD-01][fitgap:XC-03]. *Size:* S.

**O2 — ClawTeam + thin Assistant composition layer.** *Shape:* a small package owns the data objects no substrate has (Assistant, TeamTemplate, overlays, HarnessProfiles, policy, run/invocation records, Proposals) and *compiles* a TeamRun into ClawTeam CLI calls — `team spawn-team`, `task create --blocked-by`, per-Member `spawn subprocess … -- <wrapper> <rendered argv>`, `task wait`, `snapshot`, stop, `cleanup` — never `launch` (swallows errors, one profile for all, no DAG edges [ev:clawteam-probe-log#F15][ev:clawteam-probe-log#F23][ev:clawteam-spawn-platform#F12]); an explicit positional command suppresses ClawTeam's implicit profile [ev:clawteam-spawn-platform#F5], so the layer decides how the definition reaches each harness; a wrapper tees output and writes the HarnessInvocation. *Not built:* DAG, mailbox, liveness, worktrees, tmux, Surfaces, a fork, a second team substrate. *tmux-free/Windows:* `skip_permissions=false` in the layer-written config (`os.getuid()` sits inside `if skip_permissions:` [panel:judge-1.md#1]); prompts by file; wrapper-captured exit codes; unprobed off this host [fitgap:TE-08]. *Cannot satisfy:* TE-08 only documented; HB-02 Codex channel observed, not executed [ev:harness-cli-capabilities-a#F2]; TC-05 gate bypassable by a Lead calling `clawteam spawn` directly [ev:clawteam-spawn-platform#F16]; TE-05 isolation namespace-only [ev:clawteam-probe-log#F19]; AR-03 partial by design (metadata-only: manifest/lock/report, no installer — re-establishment on another host is a manual step). *Ladder:* rung 1/2 over ClawTeam, rung 6 only for the data objects listed in [reuse:§6] (the rung tally is reuse §2 "Reading across", not restated here) [reuse:G-XC-03]. *Size:* M.

**O3 — ClawTeam + HarnessBroker extension (broker as ClawTeam backend/plugin).** *Shape:* the broker packaged as a custom `SpawnBackend` registered through `register_backend`, receiving `prompt`/`system_prompt`/`command` [ev:clawteam-spawn-platform#F8]. *Not built:* definitions, templates, nesting, evolution. *Why it is a misnomer:* `register_backend` is process-local, `clawteam spawn` never loads plugins, and `BeforeWorkerSpawn` neither fires on the CLI paths nor can mutate [ev:clawteam-spawn-platform#F16][ev:clawteam-spawn-platform#F17] — so the entry point must be our own process importing "Alpha" seams with no `__all__` [ev:clawteam-spawn-platform#F15]; and ClawTeam's `is_agent_alive`/`stop_agent` handle only `tmux|subprocess|wsh` names, so a custom backend is never seen alive or dead and its task locks are never releasable [panel:judge-1.md#1][ev:clawteam-probe-log#F8]. The broker is part of the layer, not a ClawTeam backend. *Windows:* an in-process backend never calls `prepare_command` — no `os.getuid()`, no argv prompt — the one genuine advantage, Python-only. *Cannot satisfy alone:* AD, TC, TE-05, EV, AR M rows. *Ladder:* rung 2/3 on the least stable seam where the CLI seam satisfies the same rows. *Size:* M.

**O4 — ClawTeam + optional OpenClaw/Telegram Surface.** *Shape:* O1/O2 unchanged plus a Surface adapter presenting a TeamRun's *visible* Members over OpenClaw channels (`agent --deliver` [ev:clawteam-openclaw-fork-delta#F5]; bindings and per-agent `identity`, where the channel account — not the `agentId` — is the visible sender [ev:openclaw-native-and-telegram-verification#F20]) or Hermes gateway platforms with profile routing (`hermes peer dm`; no Hermes `send` command is evidenced) [ev:claude-agent-teams-hermes-openbot#F26]. *Not built:* anything that closes an M gap. *Windows:* Gateway daemon per host; WSL2 recommended [ev:harness-cli-capabilities-b#F16]. *Cannot satisfy:* whatever its core cannot; MS-01/MS-04 are already satisfied without it [fitgap:MS-01][fitgap:MS-04]; MS-02 is C-priority; the PoCs need neither OpenClaw nor Telegram (product-intent §4). *Ladder:* rung 2 for a C row. *Size:* S adapter plus two daemons' release trains and OpenClaw flag drift [ev:clawteam-openclaw-fork-delta#F5].

**O5 — upstream ClawTeam extensions (PRs only).** *Shape:* the nine bounded PRs of assumption (k) (§5.0; enumerated under "Deferred" in §5) — eight of the nine rows of [reuse:§5] (the pre-spawn mutation hook was dropped by C itself once the broker renders before spawn), with reuse §5's guard + `mcp<2` pin row counted as two. *Not built:* our objects. *Windows:* the guard/logs PRs are exactly the Windows fixes, if merged. *Cannot satisfy:* every object O1 lacks; and R2 = 1 — HEAD `0119833` unchanged since 2026-05-09, 22 open PRs, #159/#165/#167 unanswered [ev:clawteam-spawn-platform#F24]; #82/#88 open since 2026-03-24 (re-verified by both judges via `gh` on 2026-08-22 — not in the evidence corpus) [panel:judge-1.md#1][panel:judge-2.md#3]. *Ladder:* rung 3, which reuse §2 reads as "never the only path" — every item has a rung-2 shadow [reuse:G-XC-03]. *Size:* S (~0.4–0.7k incl. tests).

**O6 — selective reuse of existing modules into a new small layer.** Two readings exist in the panel. *Reading 1 (A):* vendor ClawTeam's task store/mailbox/registry and *replace* ClawTeam — M–L, rung 4 where rung 1–2 satisfies TE [fitgap:TE-01]. *Reading 2 (B; adopted here):* a sourcing rule, not a layer [panel:proposal-B-independent-layer.md#2] — vendor the fork's stdlib-only `platform_compat.py` (130 lines), `model_resolution.py` (70 lines, precedence pattern) and `spawn_with_retry` (25), attributing HKUDS (MIT, no SPDX headers in fork-only files) [ev:clawteam-openclaw-fork-delta#F19][ev:clawteam-openclaw-fork-delta#F28][ev:clawteam-openclaw-fork-delta#F30]; take Hermes `distribution.yaml`, DG `.strict()` schemas and ATM ADR 0022 as *patterns* (ATM text blocked until licensed [reuse:§7]). C straddles both readings: its O6 shape vendors `store/file.py` + `transport/file.py` as the fallback that replaces ClawTeam's task/inbox [panel:proposal-C-upstream-extension.md#2] (dissent 3 in §4). *Windows:* `platform_compat` is the shim. *Cannot satisfy alone:* it needs O2/O7 to say what the layer is. *Ladder:* rung 4 exactly where it is cheapest (TE-08 shims, HB-03 pattern, AR-03 shape). *Size:* S vendored.

**O7 — a small independent Assistant/Harness layer above multiple execution backends.** *Shape:* O2's objects plus two seams (HarnessAdapter; CoordinationSubstrate) and several backends: ClawTeam, direct CLI, Claude Code native subagents/teams, OpenClaw sessions, Hermes kanban [panel:proposal-B-independent-layer.md#4]. *Not built:* DAG, mailbox, liveness, UI, Surfaces. *Windows:* the `direct` launcher (own `subprocess`, `shell=False`, file-delivered prompts) is the cleanest tmux-free path for solo runs and ensemble legs. *The evidence on the extra backends:* Claude Code teams are experimental, Claude-only, interactive-only, non-nested [ev:claude-agent-teams-hermes-openbot#F2][ev:claude-agent-teams-hermes-openbot#F6][ev:claude-agent-teams-hermes-openbot#F7][ev:claude-agent-teams-hermes-openbot#F8]; OpenClaw `sessions_spawn(runtime:"acp")` needs the Gateway and the absent acpx plugin; its ACP config carries `agent/backend/cwd/mode` only, so persona delivery to an ACP child is unevidenced (`?`) and native sub-agent children receive only `AGENTS.md` + `TOOLS.md` [ev:openclaw-native-and-telegram-verification#F16][ev:openclaw-native-and-telegram-verification#F14][ev:harness-cli-capabilities-b#F12]; Hermes kanban is Hermes-only and un-nestable [ev:claude-agent-teams-hermes-openbot#F25]. None can host a mixed-harness nested TeamRun today [fitgap:TE-03][fitgap:TE-05]; B concedes "multiple backends is thinner than the slogan" [panel:proposal-B-independent-layer.md#8]. *Cannot satisfy:* TE-08 docs-only; HB-02 Codex; AD-05/EV-04 heuristic. *Ladder:* rung 2 + 6 like O2, plus a seam built before a second team substrate exists (XC-03 bent, not broken). *Size:* M–L (B's table sums ≈11.6k; most of the excess is scope the register does not demand [panel:judge-1.md#3]).

**O8 — a new implementation.** *Shape:* own DAG, mailbox, registry, spawn, archive. *Why not:* the TE layer is "not genuinely new — reachable at reuse rung 1–3" [fitgap:TE-01]; ClawTeam's DAG/inbox/registry are `S!` probe-verified [ev:clawteam-probe-log#F7][ev:clawteam-probe-log#F9][ev:clawteam-probe-log#F13]; ATM's lesson: "do not build a mailbox runtime" [ev:atm-salvage#F22]. *Ladder:* rung 6 with rung 1–2 available — violates XC-03. *Size:* L; months to a PoC.

**Ranking (owner tiebreak, adopted):** O2 + seams (the composition of §5) > O7 (B) > O5 filed-not-depended-on > O6 selective vendoring (`platform_compat.py`, `model_resolution.py` pattern, attribute HKUDS) > O3 (misnomer: the broker is part of the layer, not a ClawTeam backend) > O1 (fails M rows EV-03, AD-05, TC-05, TE-05, HB-01/03) > O4 > O8 (not justified by evidence).

## 3. Pressure-test walkthroughs under the recommended layer

All eight walk on the composition of §5 (mechanics → new vs reused → evidence) under the owner's assumptions (a)–(l) of §5.0; the three that carry the mechanics are: (b) the layer never passes `--task` through `clawteam spawn` — the wrapper delivers the whole bundle (persona, principles, coordination section) from a file and `skip_permissions=false` is written into the layer's ClawTeam config, so no multi-line prompt transits argv on any OS (ClawTeam builds its prompt only when `task` is given and the generic adapter branch appends `-p` only `elif prompt:` [panel:judge-1.md#1][ev:clawteam-probe-log#F12]); (c) every `clawteam spawn subprocess` exit, clean or not, runs `lifecycle on-exit` (task reset + "exited unexpectedly" to the ClawTeam leader; `--no-keepalive` does not suppress it) [ev:clawteam-probe-log#F14][panel:judge-1.md#1], so one-shot legs use the `direct` launcher and register nothing in ClawTeam; (g) ClawTeam state is read through CLI `--json` and `team snapshot`; the only internal file read is `spawn_registry.json` (pids for stop-before-cleanup) [ev:clawteam-probe-log#F13][ev:clawteam-probe-log#F20].

**PoC A — same Assistant on Codex / Claude Code / both + synthesis.** *Mechanics:* `ats run --assistant code-reviewer --harness codex` on the `direct` launcher (no ClawTeam team). The overlay resolver produces the effective definition + hash; the HarnessBroker resolves policy (user > Assistant > team > default, deciding layer recorded) and prepares one injection bundle (persona + principles text, skills dir, permission intent, output schema) with `bundle_hash`; the codex adapter renders `codex exec -c developer_instructions=<text> --json --output-schema review.json -C <ws> --ephemeral`, the `AGENTS.md`-in-`CODEX_HOME` fallback recorded as `degraded[]` [ev:harness-cli-capabilities-a#F2][ev:harness-cli-capabilities-a#F17]; Run 2 renders `claude -p --bare --append-system-prompt-file <bundle> --output-format json --json-schema review.json` [ev:harness-cli-capabilities-a#F19][ev:harness-cli-capabilities-a#F10]; the wrapper tees output, captures the exit code, parses `session_id`/`total_cost_usd` (Claude) or tokens only (Codex, `cost_source: unavailable|derived`, assumption (l)) and writes the HarnessInvocation [model:harness-broker-model#7]. Run 3 is an Ensemble record: two legs sharing `bundle_id`, each in its own workspace with its profile's isolation knobs, then a third recorded invocation whose prompt carries both structured outputs labelled by invocation id and whose schema requires `agreements[]/disagreements[]` with source ids [model:harness-broker-model#8]. Pass check = hash of the definition directory before and after. *New:* schemas + validator, resolver, profiles/policy, two adapters, broker, wrapper, ledger, Ensemble record. *Reused:* every harness flag. *Preconditions:* the Codex and Claude day-one probes of assumption (j) [fitgap:HB-02].

**PoC B — fresh TeamRun, hidden temporary Member, mixed harnesses.** *Mechanics:* `ats run development --repo R --task T` → the run layer resolves three Assistants, the broker binds a harness per Member, `run.json` is written before any process starts [model:team-execution-model#3]; the ClawTeam adapter (`CLAWTEAM_DEFAULT_BACKEND=subprocess`, optional per-run `CLAWTEAM_DATA_DIR` [ev:clawteam-probe-log#F3]) runs `team spawn-team run-X -n lead` first (the first spawn into a new team becomes ClawTeam's leader [ev:clawteam-model#F5]), `task create --blocked-by` from the workflow skeleton (ids validated by the layer [ev:clawteam-probe-log#F7]), then per Member `spawn subprocess --team run-X -n <m> -- ats-wrap <invocation>` with fully rendered argv (Lead on Claude Code, Implementer on Codex, Reviewer on Codex or Hermes `chat --source tool -q … -p <cloned profile>` [ev:harness-cli-capabilities-b#F6][ev:harness-cli-capabilities-b#F19]; per-Member command by configuration is probe-verified [ev:clawteam-probe-log#F16]). Mid-run the Lead calls `ats member add --hidden --from-ephemeral migsafe.md`; the gate checks `dynamic_members {may_create, max_count, allowed_harnesses}` *before* the substrate spawn, writes the Ephemeral Assistant into the run directory and records `visibility: hidden, origin: ephemeral, policy_decision` [model:team-execution-model#5]. `ats status` filters hidden, `ats archive` lists all; completion via `task wait run-X --agent <observer>` (explicit `--agent` avoids draining the leader inbox [ev:clawteam-model#F8]). *New:* run record, roster projections, gate, Ephemeral Assistant writer, wrapper. *Reused:* ClawTeam team/task/inbox/registry/snapshot. *Honesty (assumptions (d), (f)):* two rosters — ClawTeam's `team status`/`board show` still list `migsafe` [ev:clawteam-probe-log#F10], so PoC B's "user-facing member list" is the layer's view; the achievable TC-05 level on ClawTeam today is "gate + convention + run-scoped `CLAWTEAM_BIN`/PATH shim that refuses raw `spawn` inside a run + post-hoc roster/registry reconciliation" (the owner's words; "reconciliation" here is a post-hoc audit diff of `spawn_registry.json` against the roster, not ATM's desired-state reconciliation) — the Lead *can* bypass it by calling `clawteam spawn` directly (no pre-spawn hook on the CLI path [ev:clawteam-spawn-platform#F16]); mechanical enforcement needs the upstream hook PR or owning the spawn path.

**PoC C — nested TeamRun.** *Mechanics:* CodeMod, a Member of `ops`, runs `ats nest development --for-task t4`; the run layer checks `nesting {allowed, max_depth}`, creates inner run `run-c21d` with `parent {run_id: ops, member: codemod, task_id: t4}`, `depth: 1`, its own run directory and a ClawTeam team named by run id, created with `team spawn-team run-c21d -n codemod` **first** so the creating Member — not the first child — is ClawTeam's leader (trap 1 [ev:clawteam-probe-log#F18]); inner Members get inner identity (`ATS_RUN_ID`), fresh contexts (`--bare`, cloned profiles) and worktrees based on t4's branch — ClawTeam's `--repo` worktree is always cut from the handed repo's *currently checked-out* branch (`ClawTeam/clawteam/workspace/manager.py:59`, `base_branch` recorded [ev:clawteam-probe-log#F22]), so the layer checks out t4's branch in that repo before spawning, or passes `--no-workspace` (`commands.py` spawn option) and creates the worktrees itself (mechanism `?` until PoC C); outer `t4` is marked `delegated_to`; waiting uses `task wait run-c21d --agent codemod` (trap 2 [ev:clawteam-model#F8]) plus registry liveness. *Isolation (assumption (e)):* ClawTeam enforces no inter-team boundary [ev:clawteam-probe-log#F19]; the run records `independence.achieved: namespace` (shared data dir), `data-dir` (per-run `CLAWTEAM_DATA_DIR`, still bypassable by the global `--data-dir` flag [ev:clawteam-probe-log#F2]) or `mechanical` (inbox-ACL PR merged or spawn path owned); whether per-run data dirs break the creating Member's `task wait`/inbox discovery is settled on the first PoC C run [model:team-execution-model#13]. *New:* nesting contract. *Reused:* ClawTeam team-as-namespace, snapshot [ev:clawteam-model#F22].

**Nested TeamRun result + archive.** *Mechanics:* the inner Lead ends with `ats result --status completed --summary … --deliverables … --risks …`; the run layer writes the RunResult into the **outer** run's `run.json` (layer-owned record) and into the inner run's archive, signals the creating Member with `clawteam inbox send ops codemod <RunResult summary>` (cross-team send probe-verified [ev:clawteam-probe-log#F19]), and closes the delegated outer task with `clawteam task update ops t4 --status completed` (optionally `--description` carrying a one-line pointer to the RunResult path).
