# Existing systems fit-gap

> This document answers, for **every requirement** in the register (`product-intent.md` §3) and **every reference system**, one of the brief's six classes: *already supported · supported through configuration · supported through composition · small extension required · major extension required · architectural mismatch*. It is the factual input to `reuse-vs-build-analysis.md` (cheapest reuse rung per gap) and `architecture-options.md` (the smallest-layer decision). **It makes no recommendation.**

## Method

- Rows = requirement IDs from the frozen register (AD, TC, TE, HB, AR, EV, MS, LO, XC). Priority M/S/C as in the register.
- Every non-`n/a` cell cites at least one evidence finding `[ev:<file>#F<n>]` from `evidence/`. `S`/`C` cells require `!` confidence (as defined in the confidence-suffix bullet below); where only read/inferred evidence exists the cell is written `S?~`/`C?~` and listed under *Evidence gaps*.
- Classification is per layer, by one analyst per layer pair (AD+EV, TC+TE, HB+AR, MS+LO), each reading all ten evidence files; the owner merged the sections and checked cross-layer consistency; the W3 critic findings were applied 2026-08-22 under the owner's fix-pass decisions (D1, D7).
- **Confidence suffix (the only definition; per-layer conventions add reading rules, never another definition).** `!` = probe-reproduced on this host, or anchored to source/config `file:line`, a schema dump, verified CLI `--help` text or bundled docs with line numbers — this establishes that the mechanism *exists*; where its behaviour was not exercised the rationale says so. `~` = read from docs or inferred without a line anchor. `w` = web page only. `S?~`/`C?~`/`C?w` = would be S/C but only `~`/`w` evidence. Every `?`-suffixed cell (`?`, `?~`, `?w`, `S?~`, `C?~`, `C?w`) counts as an unverified cell in roll-ups and summaries.
- **`P` versus `Xs` ("our layer carries it" rule).** `P` is used only when the requirement is met by combining the system's existing features through configuration or prompt text alone (template fields, flags, files, a prose task). If meeting it needs the caller — the layer under study — to write run-time logic or a new record (a retry loop, a fan-out/synthesis driver, a sidecar parent link / result carrier / isolation record, a declaration object, a run-record writer or output tee), the cell is `Xs`, because that code extends the substrate from outside; such cells never rest on "our layer carries it" to stay `P`. Missing *parts* that the system simply lacks are named in Gaps and do not by themselves lower a `P`. For the DC column (scripts over installed CLIs) the same rule reads: `P` when the CLIs' own per-invocation flags/files/outputs supply the row's mechanism and the script only passes them; `Xs` when the script must implement the mechanism. Applied 2026-08-22 to TE-05 (CT/CTF), TE-07 (CT/CTF/DC), HB-04 (CT/CTF/DC), HB-05 (DC) and TC-03 (DC).
- **Multi-clause requirements.** A row's class is the least-satisfied mandatory clause in that row. A related row may isolate a concern for analysis, but it never removes that clause from the full requirement. Applied in the 2026-08-22 targeted semantic review to AD-07: its "hidden from the user UI if desired" clause remains part of AD-07 even though TC-04 analyzes roster visibility in more detail. TE-04 continues to score the narrower run-time-member lifecycle requirement it actually states. Prerequisites such as "requires a running Gateway" or "interactive session only" are recorded in the rationale and lower confidence only as the evidence dictates; they do not change the class.
- A system whose *default* contradicts a requirement but exposes a configuration switch that satisfies it scores `C` (e.g. TE-02 OC/HM: freshness by session key / fresh profile), not `M`; `M` is reserved for models that cannot be configured into compliance.
- **Best column and ties.** Best = the highest class (S > C > P > Xs > XL > M), then `!` over `~` over `w` (probe-reproduced before file:line/schema/help), then the widest coverage of the row's parts; cells tied after all three are listed in parentheses; a provisional `C?~`/`S?~` Best is written "X (C?~; else Y)". ATM never counts as Best (ideas only).
- **Roll-up column "Reuse seams observed".** The roll-up tables record, per system, which seams (config keys, CLI verbs, importable modules, hook points) the analysts observed for reuse; this column is **non-binding** and carries no decision — reuse rungs are decided only in `reuse-vs-build-analysis.md`. Likewise the XC-03 row encodes *observed* lowest rungs as `R1`–`R6` marks (not fit classes) and the XC-01 row encodes licence marks (`MIT!`, `Apache-2.0w`, `prop.w`, `none!`, `?`); both are described in their own headers.
- Demoted ATM nouns (`RoleDefinition`, `TeamDefinition`, `ProjectDefinition`, `ProjectRoleContext`, A2A, desired-state reconciliation, topic-per-Project) and other systems' words (ClawTeam "worker"/"leader", dsh "captain", DT `role`) appear only as quoted vocabulary of that system inside its own column, never as terms of this document; glossary terms (Member, Lead, Ephemeral Assistant, HarnessInvocation) are used everywhere else.
- The two consolidated lists at the end are verbatim concatenations of the per-layer "Gaps" and "Evidence gaps" lists (regenerated mechanically on 2026-08-22); the per-layer lists are the edited source.
- The ATM column classifies the **idea** ATM carried (e.g. ADR 0022's artifact model), never ATM as a runnable substrate. ATM is the owner's own repository and the owner explicitly authorizes internal copy/adaptation for ATS; its XC-01 mark is therefore `owner!`, not a claim that ATM has a public licence. Third-party notices and provenance still apply [ev:m0-product-architecture-review-2026-08-22#F7].
- Cross-cutting rows are distributed to the layer pair best placed to judge them: XC-03 (reuse ladder) under AD/EV, XC-02 (platform limits) under TC/TE, XC-01 (licenses) under HB/AR, XC-04 (auditability) under MS/LO; their formatting follows the hosting section.

## Legend

| Cell | Meaning (brief class) |
|---|---|
| `S` | already supported |
| `C` | supported through configuration |
| `P` | supported through composition (combining existing features without new code beyond glue configuration) |
| `Xs` | small extension required (bounded adapter/plugin/hook/PR; days) |
| `XL` | major extension required (new subsystem inside that system; weeks) |
| `M` | architectural mismatch (the system's model contradicts the requirement) |
| `n/a` | the system does not address this layer |
| `?` | evidence insufficient |

Confidence suffix: `!` probe-reproduced / `file:line` / schema dump / verified CLI help · `~` docs-read or inferred · `w` web-only (full rule in §Method).

## Layer AD — Assistant definition

Classification rules used in this layer (applied identically to every row; confidence suffixes as defined in §Method): single-harness definition formats (Claude subagent file, Codex agent TOML, Hermes profile, OpenClaw agent workspace, DSH record) are scored on what they *carry* in AD-01/03/08/09 and on *harness neutrality / binding* only in AD-02 and AD-04; AD-05 scores structural separation of the reusable unit from run state (project, workspace, session, identity, transcripts, task state) and refers the "bound harness" item to AD-04 so that the two rows do not collapse into one. The DC column assumes the only ready-made cross-CLI definition file is Claude's `.claude/agents/*.md` (read natively by Claude Code and Grok, importable by Hermes, script-rendered for Codex); where no file or mechanism exists at all DC is `n/a`.

## Layer AR — Artifact / dependency

*Conventions.* AR cells rate the system's **dependency/artifact metadata model attached to a definition or package** (skills, plugins, MCP servers, scripts, binaries, capability packages), not whether the system can be *given* artifacts at run time (that is HB-02). CT/CTF are rated on `--skill`, `install_clawteam.sh`, profiles/presets and `skills-lock.json`; OC/CC/CX/HM on their own package ecosystems (skills, plugins, MCP, profile distributions); DT/DG/OB/DC on whatever portable definition/export they carry. `n/a` = no dependency metadata model at all. AR-06 (added 2026-08-22 to the frozen register) is included because the register orders it inside AR.
