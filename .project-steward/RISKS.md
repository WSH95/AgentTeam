# Risks

Known risks and mitigations. Review at wrap-up when something changed.

| Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- |
| ClawTeam's alpha in-process seams, process-global event bus/config, and mutable data root can leak provider concerns or state across runs | high | high | Keep it an optional exact-revision extra; confine all imports to one compatibility module; clear/contain hooks and translate events; use opaque team namespaces; run a separate OS compatibility matrix; never use its `shell=True` subprocess backend or claim stronger isolation than demonstrated |
| ClawTeam-OpenClaw fork has structurally diverged (re-inlined per-CLI flags; 5 xfail tests) — selective reuse may be hard to keep merged | medium | medium | Classify fork features in W1; prefer upstream-friendly extension; reuse isolated modules (`platform_compat.py`, `model_resolution.py`) only with license + merge-cost notes |
| Telegram platform and OpenClaw support drift independently (managed bots, guest bots, Communities, ephemeral messages now exist at platform level but installed OpenClaw support is unverified) | high | medium | Record platform-vs-adapter capability separately; local installed-doc/dist recheck plus dated official sources; do not derive Team semantics from surface topology |
| Evidence volume overwhelms synthesis fidelity (drafters invent abstractions no substrate supports) | medium | high | Evidence schema with requirement IDs; domain models drafted after fit-gap rows exist with a mandatory "mapping to substrates" section; adversarial critics |
| ATM sunk-cost leakage (demoted concepts re-enter as architecture) | medium | medium | Glossary blocklist; critics grep for demoted nouns; ATM used only via `atm-salvage.md` |
| Harness CLIs change flags between versions (Claude Code, Codex, OpenClaw move fast) | high | low–medium | Pin versions in every HarnessCapability table; record the date; treat capability tables as HarnessProfile data, not constants |
| Workflow cost/time (≈36–45 agents) exceeds expectations | medium | low | Each workflow ≤10 agents; resume via run IDs; owner holds anchors |
| ClawTeam upstream dormant (last commit 2026-05-09, 22 open PRs; `clawteam-mcp` broken by unpinned `mcp`) — bug fixes and PRs may never land | high | medium | Pin full commit `01198332ef9270c32c5460b8a178f964fc0df451` plus `mcp>=1,<2`; isolate imports behind the CoordinationSubstrate seam; keep bounded PRs optional and plan as if none merges; a provider failure must not affect the direct core |
| Windows/macOS paths are not available on physical owner hosts; hosted CI can miss live auth/model/runtime behavior | high | high | GitHub-hosted deterministic direct-runner and optional ClawTeam compatibility jobs; no live credentials; label claims as OS/import/path/process plumbing only; retain Ubuntu owner-host live acceptance |
| Harness CLI drift (weekly releases; Codex `developer_instructions` path unverified; Grok flags partly undocumented) | high | medium | HarnessProfiles as data with verification levels; per-adapter `--help` smoke test on each version bump; day-one probes listed in the PoC plan |
| Dynamic-member creation bypasses policy if code reaches a coordination provider outside the AgentTeam boundary (TC-05) | medium | high | M1c exposes only the product-owned policy-and-spawn path to AgentTeam members; keep provider imports private to one module; audit attempted/out-of-band mutations; scope the mechanical claim to AgentTeam-mediated creation |
| Model-facing tool-call non-compliance (duplicate hops, omitted calls, prose instead of a tool call) breaks autonomous choreography on some model/harness pairs — ATM U2 0/2 on DeepSeek/OpenClaw | medium | high | Reliability as a HarnessProfile dimension (HB-01); protocol state in the DAG and structured `atm` calls; deterministic fake-harness acceptance is mandatory before live evidence; archive semantic and mechanical outcomes separately |
| Compliance vs mechanical failures conflated in evidence (ATM lesson) | medium | medium | HarnessInvocation record separates mechanical outcome (exit code, output) from semantic verification; PoC criteria name both |
| An aborted run leaves no record and no postmortem (ATM exit-137) | medium | medium | Terminal status for every HarnessInvocation and TeamRun, written before the first side effect (XC-04, TE-07) |
| LLM-dependent end-to-end evidence is flaky and costly (ATM R11) | high | medium | M1a separates deterministic evidence from live evidence, makes the deterministic tier a precondition, and caps one acceptance cycle at eight model calls with no automatic full-cycle repeat |
| Subscription OAuth is misused as a hosted/multi-user credential service, or copied into CI | low | critical | Owner-operated persistent host only; AgentTeam never brokers login/copies credential stores; hosted CI credential-free; re-review terms before any multi-user/hosted product |
| API-test provider/model drifts or is mistaken for native harness evidence | high | medium | Separate `api-test` execution mode; profile stores base/protocol/model + credential env-name only; no native-auth fallback; selection stays unset until separate approval and verification, with claims absent until a canary runs |
| PoC advisory controls are described as production security | medium | high | Every run records declared/achieved enforcement and bypasses; hidden is UI only; production acceptance requires mechanical enforcement |
| Documentation validation overclaims semantic review or owner approval | medium | medium | Keep original 54×11 structural lint distinct from targeted AD-07 semantic correction; record exact commands/results and never infer a future-dated/full-owner read-through |
| AgentTeam/`atm` names collide with similarly named public projects, Python distributions, or local commands | medium | medium | Use the namespace-qualified `WSH95/AgentTeam` repository; keep the distribution unpublished in M1a; recheck remote/PyPI/command availability immediately before rename or publication; state the product boundary clearly |
| Dedicated native-auth profiles expire or silently lose precedence to an API key/base URL/proxy inherited from the shell | medium | high | Owner logs in through each vendor CLI; `profile doctor` exposes sanitized status; native runs fail closed on conflicting environment names; never copy credentials or fall back to API mode |
| Raw model streams or workspace paths in local PoC evidence contain sensitive data | medium | high | Store full evidence only in a gitignored owner-only state directory; redact recorded argv/path/env metadata; never auto-add/export/upload; commit only human-reviewed sanitized summaries |
| Claude headless subscription accounting changes again or stale docs imply a separate monthly Agent SDK credit | high | medium | Budget M1a by calls/time, not assumed USD/credit; follow the June 15 Help Center pause over stale overview text; recheck official policy before every live cycle |
| Timeout/cancellation leaves vendor subprocess descendants alive, especially on Windows | medium | medium | One tested process runner; POSIX process-group termination and argv-based `taskkill.exe` tree termination on Windows; terminal records and post-run liveness checks |
| Python core reduces direct code reuse from TypeScript-native DSH/DG modules or makes a later DSH plugin less ergonomic | medium | low–medium | Reuse JSON/schema and mechanism ideas, not runtime modules; keep all external records language-neutral; add a small native TypeScript edge package only if DSH becomes a primary harness rather than porting the core pre-emptively |
| An exact Git dependency makes optional-provider installs sensitive to repository availability and lock resolution | medium | medium | Commit `uv.lock`; verify fresh optional-extra installs in CI; record the full revision in package metadata and compatibility reports; never make the extra part of core installation |
| Grok Build is a required first-pass harness while its active auth and definition-injection channel are unverified (M0.1 F2; `evidence/harness-cli-capabilities-a.md` §5) | medium | medium | Day-one probes recorded into the HarnessProfile before any PoC A cycle; FAIL-HARD report if the channel or auth fails; owner revisits the "all three required" gate on evidence (ADR 0018) |
| "Owner" decisions in M0 artefacts were session-authored in the owner's voice (tiebreak note, fix-pass D1–D15, assumptions (a)–(l)); later readers may treat them as human decisions | medium | medium | ADR 0018 reclassifies (a)–(l) as historical panel inputs; new decisions cite the human approval event; plans restate only what they need |
| Steward records drift from the commit they ship in (HANDOFF at `3407ec9` described a pre-commit world; PLAN claimed critic re-checks with no artefact) | medium | low–medium | Rewrite HANDOFF inside the same commit as the work it describes; every "PASS" claim names its artefact; review hygiene H7–H9 tracked in the next plan's T0 |

Further ATM-derived candidate rows (R3, R5–R10) are listed in `docs/discovery/legacy-atm-disposition.md` §4; merge on demand.
